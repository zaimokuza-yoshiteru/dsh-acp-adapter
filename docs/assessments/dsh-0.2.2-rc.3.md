# DSH 0.2.2 的三个 RC：适配器审查与 RC.3 兼容评估

2026-11-14，插件基线为已发布的 [v0.2.2-rc.2.1 / 0aef1e5](https://github.com/zaimokuza-yoshiteru/dsh-acp-adapter/tree/0aef1e55af6f28f1a04d3444975f744b736a1bb0)，与远端 `0.2.2-alpha` 相同。本地 DSH 参考仓库已切到 [RC.3 / 38a6a5c](https://github.com/deepseek-ai/deepseek-harness/tree/38a6a5c965aa99ab525161efb7cc5cf1fe62fced)，保留原有工作区改动。以下评估以该已发包为基线。分支实施与验收结果见文末。

**建议做 RC.3 适配。** 已发包不能在 RC.3 正常安装；在隔离副本中更换精确依赖、修正一个传递 peer 后，相同的生产源码可通过类型检查、单测、构建和安装启动。不需要更换 ACP 协议客户端。建议下一版同时修复两个可复现的会话/权限问题和一个新暴露的交互缺口。

三项可在插件侧落地。前两项的复现使用当前已发插件基线；第三项使用 RC.3 导入器以及官方模型选择投影，并用官方导入样本交叉核对。不能把“未知结果”“访问被拒”和“应新建会话”统称为连接失败，也不应用去掉保护来消除提示。

## RC.3 安装与依赖证据

- 以已发布 tarball 运行官方 RC.3 `dsh plugin --profile web add`，明确以不兼容退出：插件 `engines.dsh=0.2.2-rc.2`，实际宿主 RC.3，没有版本豁免。生产环境应使用匹配版本。
- 以同一插件提交复制隔离源码，将 `engines.dsh`、54 个 DSH peer 与 100 个 DSH 开发依赖对齐到精确 RC.3。第一轮 `pnpm typecheck` 的 117 个直接依赖检查、单测与构建全绿，但从实际消费包解析时发现 10 个 RC.3 包仍加载唯一旧包 `@deepseek-ai/dsh-error@0.2.2-rc.2`，不符合它们精确声明的 peer。现有[依赖检查](https://github.com/zaimokuza-yoshiteru/dsh-acp-adapter/blob/0aef1e55af6f28f1a04d3444975f744b736a1bb0/scripts/verify-dev-dependencies.ts#L10)只验证直接 devDependencies。
- 隔离副本增加精确 **dev** pin `@deepseek-ai/dsh-error@0.2.2-rc.3` 后，上述 10 处不匹配消失，没有添加用户运行时依赖。正式升级应提交对应 lockfile，并让检查从实际消费者解析已安装的 DSH 精确 peer，发现错版就失败；不要把所有第三方包强制锁到宿主版本。
- 在修正后的依赖上：Node 24.19.0、pnpm 10.7.0；typecheck 验证 118 个直接开发依赖及生产/测试/工具类型；单测 2,953 通过、3 跳过；构建验证 128 个 JS 相对引用；322 文件的候选 tarball 通过全新 RC.3 Web profile 的安装、HTTP 200/client bootstrap、卸载和配置保留检查。评估用 tarball 沿用旧插件版本号；未发布、不得用来覆盖 npm 上的同名版本。

- 真实 Web 共存：在独立 RC.3 npm Web profile 同时加载官方实验导入插件和候选 ACP 插件，用合成 ZIP 从原生按钮导入 1 个会话，在侧栏打开并读到历史回答。该 profile 没有配置 ACP 路由，也没有发送模型请求；打开导入会话后误报“正在重新连接活动记录”0 次，renderer error 0。ACP 恢复查询返回 healthy、provider 为空；审计接口 backendOf 的 blank 指没有绑定/请求头，不代表没有历史。默认 ACP 的四种组合由独立导入探针覆盖，不把这次浏览器验证算作真实外部 Agent 验收。
- 本地复核证据（gitignored）：插件下 `.local/upgrade-rc3/review/up-{1,2,3}.json` 是三个官方 change-scope 结果；`.local/upgrade-rc3/review/imported-route/result.json` 是真实导入事件与默认/显式模型的决策结果；`.local/rc3-review-independent/{fork,native-lead,import-default}.log` 为独立 reviewer 的四个复现用例；`.local/upgrade-rc3/probe/old-install.log`、`peer-pin-{typecheck,unit,build,gate}.log` 与 `coexist/browser-5.log` 分别记录旧包拒装、修正后的候选和实际浏览器结果。历史 RC.2 的实测证据只用于界定上一版能力，不计为 RC.3 的通过项。

## 能删什么、不能删什么

- [冷成员模型读取](https://github.com/zaimokuza-yoshiteru/dsh-acp-adapter/blob/0aef1e55af6f28f1a04d3444975f744b736a1bb0/src/host/teams/member-models.ts#L154)先通过唯一调用的 `readMemberRequestModel` 读取已有模型，再通过 `currentCut` 读取同一会话的选择和游标。可改为从同一次观察使用 `lastUsed/next/cursor`，删除[单用途模块](https://github.com/zaimokuza-yoshiteru/dsh-acp-adapter/blob/0aef1e55af6f28f1a04d3444975f744b736a1bb0/src/host/teams/member-model-facts.ts)，保留 provider 匹配和 Agent 已报告模型的后备值。异常路径下核对旧行为；不要顺带删除用于甄别切换后又切回的检查。
- [成员树路径](https://github.com/zaimokuza-yoshiteru/dsh-acp-adapter/blob/0aef1e55af6f28f1a04d3444975f744b736a1bb0/src/host/subagent/tree.ts#L64)为每一行重建全树 Map；目录、审批子成员均消费该路径。按一次 `listDescendants` 的结果建立一次索引即可，不跨会话或跨代缓存，不移除循环、外部成员和祖先权限检查。用宽树对照返回结果/构建次数，不声称未经测量的端到端性能提升。
- [profile-adapter.ts](../../src/host/composition/profile-adapter.ts) 有 4,682 行。先把工作目录交接的持久化与错误分类收拢到一个可故障注入的操作；派发、补存和恢复仍只有一个顺序负责人。按具体事务拆比按行数或按 Agent 复制生命周期更有价值。
- 官方 `dsh-acp` 对外提供 DSH Agent，`dsh-subagent-acp` 启动一次性子任务，`dsh-mcp-manager` 负责 DSH 消费外部工具；三者均不替代交互式外部 ACP Agent 使用本会话 DSH 工具的桥。RC.3 的 `sidebar.session.action` 包装“新建”入口，不提供已有会话 fork 的来源/截点，也不是后端切换或复制历史的入口。
- RC.3 原生日志 ZIP 会对读不到的附件生成 `attachments-missing.txt`；这使原生日志更适合导出，但不导出 ACP sidecar、绑定或远端会话。Windows 修复的是 [NSIS 更新辅助进程的工作目录](https://github.com/deepseek-ai/deepseek-harness/blob/38a6a5c965aa99ab525161efb7cc5cf1fe62fced/apps/desktop/installer/restart-status.h#L66)，不替代 Devin 子进程的退出验证。已有会话切模压缩、通用原生分叉和 Auto Review 的既有边界均未因此解除；保留现有替代入口。

建议先锁定精确 RC.3 验证环境，再分别修复工作目录交接、混合 Teams 权限和导入路径的应用内出口。发布前验证原生/ACP 混合 Teams 和无权限反例、普通空白会话不闪恢复提示、导入前后两种默认模型与取消、插件热停启、创造模式和中英文 390px；跨平台 CI 与 RC.3 独立桌面、真实 Agent 的结果单独记录，不能用 RC.2 的发布验收替代。

## 分支实施与验收

`0.2.2-alpha` 的未发布候选为 `0.2.2-rc.3.1`。宿主要求和 DSH 依赖已锁定官方 RC.3。开发依赖显式固定 `dsh-error`，安装检查从每个 DSH 消费包的实际位置验证依赖和 peer。缺失的必需 peer 和实际安装的错版可选 peer 均会报出消费方。

- **工作目录切换。** 收到子会话 ID 后，在一个 SQLite 事务中更新绑定、健康状态和审计。临时存储错误只重试本地写入。故障注入覆盖审计失败、健康状态写入失败、确认丢失、停止请求、通知回调异常、目录再次改变，以及重新打开数据库。如果进程在保存子 ID 前退出，磁盘只剩分叉意图，恢复流程保留人工确认。[工作目录测试](../../test/unit/host/profile-adapter-working-directory.spec.ts) · [事务测试](../../test/unit/persistence/sidecar.spec.ts)
- **混合 Teams。** 原生主会话沿宿主子代理树发现可访问的 ACP 成员。休眠目录使用只读观察，权限不足的路径在读取成员模型前过滤，活动与审计保留 ACP 归属检查。一次目录读取构建一个索引，一次成员会话观察同时读取当前模型、待选模型及游标。[Gateway 权限测试](../../test/unit/remote/resource-access.spec.ts) · [浏览器混合成员流程](../../test/e2e/teams-boundaries.e2e.ts)

## 专用 ACP 预设能否原地切模

在隔离副本中仅对专用 ACP 预设放行原地切模。通过 RC.3 原生会话 API 和独立 ACP 子进程验证，同一远端会话确认 A → B 后可以接收下一条消息。插件热停启后，新进程也能加载原会话、确认 B 并续聊。标准预设的切模保护继续生效。

当 Agent 拒绝 B、回复仍是 A、撤回模型选项或写入 B 后断连时，四种情况均在发送下一条消息前停止。此时宿主请求头已经记录 B，远端实际模型可能是 A 或 B。面向用户开放之前，需要能够分别恢复所选模型和已确认模型，并验证真实 Agent 切到更小窗口时如何保留历史。本版各预设切模均沿用另开会话。
