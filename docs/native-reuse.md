# 原生复用与保留边界

本轮按 UI、运行时、构建与依赖三个模块核查；兼容目标以 `package.json` 的 `engines.dsh` 为准。

| 范围 | 实现与边界 |
| --- | --- |
| 会话执行状态 | ACP 只定义执行事实的增量 fold，DSH `sessionProjections` 负责驱动、缓存与恢复；输入准入、历史判定、开放轮次和 fork 标记共用这一状态。提交水位直接读取 `Session.seq`，权限读取宿主 `permissions` 投影；运行时释放仍匹配原始 Session 对象，避免读取封装影响生命周期。 |
| 对话与活动 | ACP 通知归一化为 DSH stream 和活动数据，再使用宿主消息、工具详情与 JSON 组件；执行仍属于外部 Agent。 |
| 客户端类型与构建 | React 使用官方开发类型，运行时仍由宿主提供；构建和验证共用平台模块清单，reference 门禁与上游源码比对。 |
| 审批与成员模式 | 原生审批负责当前请求，团队摘要转发原始审批；仅本次允许、拒绝和逐 Agent 类型批量模式规则保留。原生权限选择器不替换。 |
| 进程与期限 | 继续复用宿主 subprocess 与 timeout；ACP 保留协议连接、取消收敛和错误分类。 |
| 文件写入 | 保留字节内容、拒绝最终符号链接、哈希审计和并发校验。宿主文本写入会规范化换行，不能直接等价替换。 |
| 成员模型 | ACP 主会话面板提供同一 profile 内的成员模型选择；公开 `installModelSelection` 同时驱动提示词、请求配置和模型变更说明，`llm.resolveCallConfig` 使用新模型的默认思考配置。选择绑定原 ACP 会话，休眠恢复时重新应用，不写全局默认。运行中或待审批时不可修改。 |
| Teams 通信 | 保留 ACP 到宿主 Teams 的 MCP server bridge；宿主 MCP client 和无人值守 ACP 子任务不能承担这一角色。 |
| 本地数据 | Sidecar 继续负责绑定、dispatch 状态与诊断事务；宿主 Session 日志和通用 KV 不提供等价事务。新增执行投影是可重建缓存，不修改 Session 格式或 Sidecar schema，无需清理历史数据；旧会话首次使用可能需要从已有事件重建投影。 |

已删除手工 React 类型声明、重复历史扫描以及仅测试调用的 journal 包装方法；活动测试直接覆盖生产使用的 replace/append 接口。未发现可以直接删除的整份运行时模块。动态加载的 stdio MCP bridge、历史 payload 测试夹具以及子进程测试入口均有实际用途。上游公开接口不能保持现有行为时，保留必要适配，避免引入另一套私有宿主依赖。

本轮验证结果记录在 [回归记录](../test/e2e/REGRESSION.md)。

成员模型选择新增一张按会话与 binding 保存的小型 Sidecar 表，旧数据库自动建表，无需清理数据。原生 Teams 名单的模型文案仍由宿主维护，未修改其展示。当前 ACP 模型目录没有逐模型图片能力声明，延续既有 ACP 图片能力校验；若未来声明不同模型的图片能力，需要同步适配宿主 continuation 仍读取初始模型的图片准入路径。
