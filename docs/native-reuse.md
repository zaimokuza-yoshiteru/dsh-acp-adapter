# 原生复用与保留边界

[English](native-reuse.en.md)

当前开发分支的兼容目标是 DSH `0.2.2-rc.1`，以 `package.json` 中精确锁定的官方 npm 依赖为准；上游源码只作测试 scaffold。README 中的安装命令对应已发布版本。DSH 负责输入准入、宿主工具和原生展示；外部 Agent 负责模型循环、自带工具权限和私有上下文。适配器在两者之间转换协议数据，并保留公开接口尚不能等价提供的连续性、权限和持久化能力。

## 会话与输入

DSH 原生 inbox、pre-step 和 Session 消息持久化负责输入准入。适配器只向 ACP 发送已准入的当前输入，不自行重建 AgentLoop 或重放普通用户历史。仅当普通非分叉会话始终使用同一 ACP 路由、从未建立 ACP 绑定且没有 ACP 执行记录时，首次 Agent 会话可接收该路由此前已准入但未交付的对话与指令；不重放切换到该路由之前的历史，明确空白重置也不采用此路径。运行中输入只有在当前 ACP 连接明确声明安全注入能力时才可能注入；其他交接路径会取消旧 prompt，等待结果与审批结算，再在同一 Agent 会话续发。Agent 原生 CLI 的能力不能替代连接声明。DSH 的有效运行上下文和 skill 目录可以传给 Agent，但不会安装 Agent 私有 skill 或授予新工具、权限。模型目录、推理强度和搜索沿用 DSH 原生选择器；Agent 自有模式与成员选择仍绑定各自的 ACP 会话，不改写全局默认。

ACP `category` 是专用界面的增强信息，不是连接或首次 prompt 的必要条件。成功探测未得到可选择的 `category=model` 目录时，适配器提供“Agent current configuration”入口，继续使用 Agent 当前配置；缺失或未知分类的选项（包括 ID 为 `model` 的选项）仍作为普通会话配置显示并提交。认证或探测失败仍保留失败状态，不生成该入口。

“当前配置”使用插件自有的宿主路由标识，不作为模型值发送给 Agent，也不宣称已知其实际模型、容量或计费。Agent 声明的真实模型仍沿原生目录选择；与插件保留命名空间相撞的真实值先编码为不同路由，再在 ACP 配置 RPC 前解码。现有普通模型 ID 保持原样；该方案没有把全部 ACP 会话迁移为稳定 Agent 路由，也不代表宿主压缩已经兼容。

CodeBuddy 的逐模型推理档位发现以实际 `initialize.agentInfo.name=codebuddy-code` 握手和有效的 `category=model` 选择器为依据，复用现有临时会话探测；只填写 runtime 名称不会让通用 Agent 被额外切模。某个模型探测失败时不借用默认模型的档位，探测不发送 prompt。

执行事实由 ACP 适配层归一化，交给 DSH `sessionProjections` 驱动和恢复；投影是可重建缓存。Sidecar 仍保存 ACP 绑定、派发状态和诊断事务，原生 Session 日志或通用 KV 没有等价的事务语义。历史记录不因切换投影而改写或清理。显式空白重绑定只补发当前宿主有效投影中的 AGENTS 指令，保留其顺序和替换、删除语义；正常续聊和已有会话恢复不重复发送。

远端终态已确认而本地结果暂未写入时，当前 Host 会补存，后续输入等待结算，不重放已完成的工具；该待补存状态不保证跨 Host 进程续接。远端是否接受请求仍不明确时则保留恢复门禁，不自动重发或以空白会话掩盖上下文丢失。暂时读取故障可重试；稳定错误应显示不可用，不能当作空记录。ACP sidecar 记录不在 DSH 原生会话日志 ZIP 中；导出与分享见 [README 排障说明](../README.md#排障与反馈)。

目录或传输在输入准入后、ACP prompt 派发前失效，且没有待接管的 Agent 自动回合时，运行时明确报告 `ACP_PROMPT_NOT_DISPATCHED`。适配器只清除该次输入的派发保护，保留原绑定和已消费历史位置；重试恢复同一 Agent 会话，不要求空白重置。清理写盘失败仍由本地补存门禁保护；真实派发或自动回合的未知结果不采用该路径。

在途执行、恢复门禁和本地补存队列由显式 Host 根服务 `acpHostContinuity` 的独立 owner 持有。同一 Host 的插件热重装复用这些 owner，不清空尚未结算的状态；不同 Host 和独立 adapter 不共享模块级 registry。Host 最终关闭先停止新资源借用、新结算 sink 和后台重试，等待 registry 的工具、fork 登记、投影及最终写入收尾，再释放依赖、Sidecar 和剩余队列。清理失败仍尝试后续资源释放并报告错误，不把强制撤销依赖当作工具已完成。

携带父会话已完成历史的普通分支，必须核实父绑定、空闲状态、最新语义截点与实际 ACP `session/fork` 能力。无法证明这些条件或 fork 失败时，不会调用 `session/new` 将空白会话冒充历史继承；已派发但结果未知仍保留恢复门禁。公开执行 guard 只在 `subagent_fork` 参数明确指定 ACP 目标、且父会话已有完成历史并正在运行时提前拒绝。该工具允许显式选择原生子会话，公开工具定义又不暴露省略参数后的实际默认路由，因此不能按父会话使用 ACP 就隐藏整个工具或拒绝 Teams fork。原生目标保留宿主准入；未知默认目标、自定义工具和直接子代理服务由最终目标的 seeded-fork 准入兜底。锁定宿主尚无供适配器使用的完整目标路由解析、原生分支菜单与创建前能力预检；菜单可能仍可点击，DSH 分支记录也可能先创建，但这不允许 ACP 空白降级或后续 prompt 派发。

普通会话界面的 ACP 分叉仍由原生 `ClientSessions.fork` 创建、编目并处理标题。适配器在 Host 核验源／子双资源权限和精确 seed 后，单独保存来源，不恢复已移除的 `parentSession` 关系。页签级 `sessionStorage` 只记录 Host Sidecar 随机标识、源会话、截点、创建阶段和已确认的子会话 ID；它不构成授权。插件停用等待已接纳的原生调用结算，不依赖同期撤销的 Remote 完成登记；同一页签重新启用或刷新后，显式重试沿用已记录的子会话。创建结果未知时阻止重复创建，存储不可写时在派发前拒绝；创建后存储突然失效则保留未知状态，不猜测子会话。关闭页签、清空站点存储或浏览器强制退出不在该恢复保证内。

## 工具、权限与可选能力

Qwen Code 的后台任务与定时轮次通过原生 jobs 和 AgentLoop 承接。后台任务完成通知只唤醒并承接 Qwen 已开始的轮次；同批其他输入在该轮确认结束后顺序发送。自动回合只有匹配会话／轮次且原因受支持的显式终态才能正常结算；未知、空白或缺失原因保留结果未知，并阻止同批其他输入继续派发。已宣布的后台轮次若先收到匹配的 `turnComplete:true, partial:true` 响应标记，后续 `end_turn` 也按结果未知处理；明确取消等其他终态保留原义。上游异常若未提供任何不完整标记，适配器无法可靠识别。active-work 快照只反映活动性，hold 消失、模型 usage 或静默均不证明整轮成功或取消。当前 Qwen cron／loop 缺少整轮终态标记，承接其输出后只能在报告失联时进入结果未知恢复，不能签作成功完成。Stop 未获远端确认时关闭连接并保留未知结果。Qwen 问答使用原生问题面板；私有扩展只应用于已确认的 Qwen Agent。协议夹具与真实 Agent 的覆盖范围见 [E2E 指南](../test/e2e/README.md)。

工具桥只暴露 DSH 为当前已准入请求组装、且在会话作用域内仍有效的工具，借用宿主本步已准入的同一个 `ResolvedToolSet`，经所选 native 或 PTC 执行器的批次 `tools.execute` 完成参数检查、钩子和工具规则。PTC 的 `run_code` 是执行器私有传输入口，不要求它存在于普通工具注册表；工具被移除或作用域收窄后，旧目录中对应目标的准入失效。已确认来自当前桥但名称未注册的工具请求直接拒绝，不让用户批准无法执行的调用。Agent 自带的 shell、文件和模型调用仍归 Agent 所有，不会因桥接而变成 DSH 工具事件；依赖原生模型调用、PTC 内部调用身份或 loop 控制权的插件仍须单独适配。宿主 MCP client 或一次性外部子任务也不能替代交互式 ACP 会话与 Teams 通信桥。

ACP 的 Auto/Ask 只处理 Agent 实际发出的 DSH 工具授权请求；Ask 显示该请求供用户确认，不会要求每次工具调用都弹出审批，也不改变 Agent 模式。该设置不等于原生 Auto Review 的 LLM 风险评审，也不能扩大 DSH 工具权限。团队成员实时读取已认证 Lead 的策略，普通受管子会话与独立分支保存自己的策略。Devin 的 ACP 授权请求不包含可靠的企业 Ask 来源证明，因此即使选择 Auto，也由用户回答实际发出的授权请求；适配器不会自动选择一次、永久或 bypass。其他 Agent 保留已有的工具身份与选项校验。企业拒绝及 Agent 自有权限仍由相应权限系统执行，不能通过父页面或切换执行身份解除。

无歧义的一次允许／拒绝复用原生审批，父页面回答子会话原有的 pending carrier。多选授权保留原始选项、ID 和范围，通过真正的运行时根会话呈现原生问题卡；根会话只拥有展示交互，决定仍回复原始子 ACP 请求。`session/request_permission` 的子会话 Sidecar 审计记录展示来源；Codex elicitation 沿用自身的答复路径，不伪造该权限审计记录。Host 在呈现及接受答案时核验存活实例和每层 ownership；取消、连接失效或实例替换后的迟到答案不再生效。不将多范围选项缩为一次，不为它们增加批量批准，也不重发工具操作来恢复审批。

该呈现不依赖 Teams，也不改变子会话对 DSH 工具的原生委派 `never` 策略。普通独立分支与只读外部子任务投影不按受管子会话处理。跨会话列表逐层检查资源访问；锁定版本的 Gateway 只向 owner 客户端发送交互请求并接受回答，根会话展示不会将子详情广播给只读客户端。普通澄清和计划审核保留原生调用者限制；只有已识别的 ACP 授权请求，以及身份核实后的 Codex 权限范围表单使用代呈。原生服务继续拥有问题卡、等待和答复，适配器仅关联原始请求与展示生命周期，不新增审批 broker 或用户开关。

RC.1 在已有 ACP 会话切模时会强制检查模型容量；目录未提供容量便在 ACP prompt 前报 `MODEL_SWITCH_COMPACTION_FAILED`，包括唤醒已改选模型的成员。插件在现有会话选择其他模型时提前提供保留当前模型或创建独立新会话的出口，并在 Host 准入处拒绝绕过界面的更换。新会话不继承旧对话历史。已有 Teams 成员的其他模型禁用，但仍允许选择已提交的当前模型，清除迁移前遗留的待生效选择；创建成员的首次模型选择及同模型推理强度调整仍保留。默认模型不因这些会话操作改变。

这层保护避免用户落入已知切模错误，并未实现现有会话的模型切换压缩。插件不编造模型容量、不吞压缩失败、不改宿主共享预设的自动压缩；完整切模与辅助压缩仍需独立的宿主生命周期支持。

原生 Auto Review、自动标题和 `/compact` 的辅助模型调用目前没有完整的 ACP 会话准入身份，不能承诺与普通 ACP prompt 等价。

ACP 文件写入保留原始字节、最终符号链接拒绝、暂存后发布前的内容哈希复查与新建文件冲突保护。宿主 `writeText` 原样写入 UTF-8 content，仅返回的 diff `after` 规范为 LF；不能直接替代的原因是宿主解析路径会跟随最终符号链接，且其版本检查发生在暂存前，与上述保护时点不等价。原生 `create_worktree` 或 `working_directory` 工具改变目录前须确认 Agent 支持保留上下文的 `session/fork`；支持时在旧执行与宿主工具结算后交接绑定，不支持时在 Git 或目录副作用前拒绝。已知待交接状态可继续完成，派发结果未知仍须人工恢复。Forge 首轮建树发生在初始 ACP 绑定之前，可直接使用目标目录；其空闲时“回到项目”通过工作目录服务直接切换，不经过工具 guard，已绑定 ACP 会话下一次输入会进入恢复门禁，包括支持 fork 的 Agent。RC.1 没有该服务的公开变更前准入钩子，适配器不修改官方服务，也不会悄悄建立空白会话。

面向用户的官方可选组合包通过 DSH 原生 Plugins 入口启用，适配器不增加第二套开关。安装、代码导入、服务激活和当前会话可用性是不同状态；Teams 界面入口随官方贡献的启停撤销或恢复。ACP 图片能力只在当前调用者、Session、同代运行实例、已确认模型及有效连接相符时提供给原生工具，未知能力不冒称只支持文本。官方 `appendPluginRecord` 的写入范围不涵盖本插件，不能用它替换 Sidecar。

远程界面操作沿用 DSH 的调用者与会话资源授权；团队管理涉及 Lead 和成员时同时校验两者范围，跨会话列表只返回调用者当前可读的条目。它与 Agent 工具审批分别生效，不增加 ACP 登录或权限配置。Teams 创建策略与身份上下文使用原生指令，适配器只保留共享工作区与 fresh-only 等实际能力限制。

工具目录变化按目标撤权，不因目录暂时为空而关闭仍有效的 MCP 连接。待审批请求绑定原工具注册和 prompt 代次，撤权会取消问题，回复前再次核验；无关工具与 Agent 自带权限不受连带影响。新注册即使同名、同 schema 也不能继承旧授权。新的安全请求重新准入目录；已暂停 prompt 的目录身份变化时先排空旧执行，再按 Agent 的恢复能力继续，不能通过 steering 绕过恢复。服务或 Agent 本身撤销仍关闭连接。批次失败只输出脱敏、限长的消息和结构化字段，不记录任意 cause 对象。

普通表单保留每个 schema 字段及其说明；可选字段经原生“跳过”后省略，`items.anyOf` 保留多选语义。字段名后缀不能证明问题关联，因此不自动合并 `_custom` 字段。必填项及已识别的权限范围没有明确答案时取消。原生问题卡仍可能显示独立的可选页，这不等于已实现无须跳过的可选字段表单。

## 展示与可观察边界

显式 live 诊断由 Host 根服务 `acpLiveDiagnostics` 或独立检查运行自己的 collector 持有，默认没有 sink、不会额外写日志。同一 Host 热重装保留诊断 owner，不同 Host 或运行的 sink 相互隔离。撤销时停止新记录并等待已接纳的写入，写入失败保持可观察；诊断不是授权或结果完成的证据。

诊断视图、Agent 控件和插件配置页只在 `(hover: hover)` 设备上显示悬停反馈，触屏保留选中、展开、禁用和键盘 `focus-visible` 状态。窄屏诊断工具栏允许筛选与操作组换行，搜索框按剩余宽度伸缩，保留全部入口。390px 明暗触屏回归使用 Chromium 的真实输入能力模拟；窄桌面窗口或 Electron 的普通窗口不能替代这项触屏验证。

ACP 终端的增量输出交给原生 jobs 输出流保留和展示，ACP 自身的输出快照保持独立。活动终端和已结束但尚未释放的终端保留原生记录与可读输出；确认进程范围退出、完成原有 release 审计流程且原生 waiter 确认终态后，释放终端会移除该展示记录，Sidecar 与 Session 历史仍保留。任务分组、停止、已结束条目的“清空”沿用原生界面；“清空”只在当前组件中隐藏条目，不删除后台记录，也不停止活动任务。Qwen 单任务取消回执只表示请求结果，取消失败或未确认时保持原生 `stopping` 并显示进度说明；取消后的正常任务结算只依据明确的终态通知或快照，时间经过或任务从快照消失都不证明停止。连接关闭时等待已有的进程范围清理；无法确认退出时明确报告清理失败，不冒称任务已终止。

工作步骤展示和收起时机沿用 DSH 原生设置。已有原生提交消息的 ACP 回答保留原生归属，遵循“全部／最后回复”偏好，不再强制提升到 turn 层；过程内容仍可收起，最新原生回答继续拥有轮末操作。ACP journal 聚合节点属于整轮过程，不单独构成分析步骤；空 journal 不生成已完成的分析组或额外间距。ACP 自有详情卡片也使用原生 disclosure：真正收起外层过程时重置内层展开，单纯切换展示模式则保留手动状态。为兼容锁定版本的渲染器，私有 slot 保留注册别名，仅将 DOM `data-slot` 恢复为原生名称，行间距继续由原生 CSS 管理。

ACP 通知先归一化，再交给 DSH 原生 Assistant、工具树、Diff、计划和过程分组展示；原生会话继续使用原有渲染器。缺少退出状态、文件总行数或旧记录内容位置时，显示已有事实或通用详情，不补造数字、顺序和宿主执行事件。ACP 工具没有原生轨迹事件时不显示“查看”跳转，不用 JSON 弹窗替代轨迹。单一且匹配文件目标的绝对 location 用于历史文件卡打开，避免随当前工作目录改变。截断的诊断内容不能作为完整 Diff；ACP 计划只投影为观察状态，不反向调用 `todo_write` 或强制完成未结束的任务。

会话活动卡中的插件生成工具占位标题、终端、文件差异与资源内容标题由客户端 locale 展示；标题来源依据结构化标记和活动身份，不把英文文案当作状态。Agent 原始标题保留原文，旧记录缺少来源标记或超大明细已截断到不可解析时保守保留原文。原生模型选择器中的“Agent current configuration”仍受 RC.1 单一 label 插槽限制：该插槽无法按模型回退，强制接管会影响其他插件，因此本插件不覆盖它；原生 aria/title 与 `/model` 名称也未改写。

DSH `0.2.2-rc.1` 的原生“本轮改动”摘要依赖原生 Session `tool/result` 事件；纯 ACP 自带工具轮次不会自动生成该摘要。桥接的 `tools.execute` 虽会经过真实执行钩子，也不等于原生 AgentLoop 已追加该 Session 事件。单次编辑的原生 DiffBlock 与整轮摘要是两条不同链路。“显示代码工作视图”只显隐已有的改动卡片，不补采集文件变更。显式 Markdown 文件链接仍可使用原生预览；行内代码文件名的自动链接依赖原生已记录的产物或交付记录。

批次 API 已能按已准入步骤记录桥接的宿主工具调用，本插件尚未启用这条独立日志链路；公开宿主接口仍不能保证捕获 Agent 内部文件操作。ACP 提供的真实差异可交给原生 DiffBlock；上下文用量仍以 Agent 报告为准。外部子任务只有通过来源、身份与自身终态核验后才成为只读子会话，结果摘要不冒充完整私有历史。无法表示的附件或输出会明确说明，不静默丢弃。

Agent 的 `usage_update` 继续提供上下文占用展示。`session/prompt` 响应中的 token 用量暂不写入 DSH 原生精确统计：尚无跨 Agent 的可靠契约证明这些计数属于本轮还是会话累计，输入计数也可能已包含缓存。恢复、分叉和重启后的累计基线同样不能推测；只有明确这些语义并转换为 DSH 每次请求的互斥输入／缓存桶后，才能启用该统计。

验证场景见 [E2E 指南](../test/e2e/README.md)，发布与回退见 [发布指南](releasing.md)。
