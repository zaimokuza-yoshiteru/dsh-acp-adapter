# 原生复用与保留边界

[English](native-reuse.en.md)

兼容目标以 `package.json` 的 `engines.dsh` 和锁定的官方 npm 依赖为准。上游源码仅用于浏览器测试 scaffold，不替换发布依赖。

DSH 负责输入准入、宿主扩展与原生展示；Agent 负责模型循环、权限决策和上下文管理。适配器先归一化协议数据，再交给原生组件。上游公开接口无法保持现有行为时，保留必要适配。

| 范围 | 实现与边界 |
| --- | --- |
| 会话执行状态 | ACP 只定义执行事实的增量 fold，DSH `sessionProjections` 负责驱动、缓存与恢复；输入准入、历史判定、开放轮次和 fork 标记共用这一状态。提交水位直接读取 `Session.seq`，权限读取宿主 `permissions` 投影；运行时释放仍匹配原始 Session 对象，避免读取封装影响生命周期。 |
| 运行中输入 | 使用原生 inbox、pre-step 和消息持久化。默认仅取消 ACP 执行并等待确认，原生 loop 接续新 step；协商支持原子注入时，一个 ACP prompt 可跨原生 step 输出。拒绝输入、切换路由和结束 turn 时回收挂起执行，不公开或调用私有 inbox.claim。 |
| 对话与活动 | ACP 通知先按持久化内容位置展开为原生对话节点，再交给 DSH 原生过程分组、Assistant 和 ToolCallTree；工具渲染器、依赖注入和语言沿用宿主。MCP 封装还原为工具名与参数，真实命令映射为 Bash/PowerShell。紧凑、详细和展开模式、思考摘要、间距、过程标题及折叠由宿主设置决定，调用数量作为归一化数据传入，不强制显示旧版计数标题。原生会话沿用原渲染器；旧记录缺少位置或第三方渲染器不兼容时保留活动回退，不猜测顺序，不伪造宿主执行事件。 |
| 客户端类型与构建 | React 使用官方开发类型，运行时仍由宿主提供；构建和验证共用平台模块清单，reference 门禁与上游源码比对。 |
| RPC 元数据 | 直接使用当前宿主的官方 Typert generator 和严格 codec factory；Host 和 Remote 共用原生契约。 |
| 审批与成员模式 | 原生审批负责当前请求，团队摘要转发原始审批；仅本次允许、拒绝和逐 Agent 类型批量模式规则保留。原生权限选择器不替换。 |
| 进程与期限 | 继续复用宿主 subprocess 与 timeout；ACP 保留协议连接、取消收敛和错误分类。 |
| 文件写入 | 保留字节内容、拒绝最终符号链接、哈希审计和并发校验。新建文件时，若其他程序抢先创建同一路径，会报告冲突并保留对方文件；已有文件仍采用写前哈希复核，不保证跨进程事务。宿主文本写入会规范化换行，不能直接等价替换。 |
| 成员模型 | ACP 主会话面板提供同一 profile 内的成员模型选择；公开 `installModelSelection` 同时驱动提示词、请求配置和模型变更说明，`llm.resolveCallConfig` 使用新模型的默认思考配置。选择绑定原 ACP 会话，休眠恢复时重新应用，不写全局默认。运行中或待审批时不可修改。 |
| Teams 通信 | 保留 ACP 到宿主 Teams 的 MCP server bridge；宿主 MCP client 和无人值守 ACP 子任务不能承担这一角色。 |
| 本地数据 | Sidecar 继续负责绑定、dispatch 状态与诊断事务；宿主 Session 日志和通用 KV 不提供等价事务。执行投影是可重建缓存，不修改 Session 格式或 Sidecar schema，无需清理历史数据；旧会话首次使用可能需要从已有事件重建投影。 |

工具事实不足时使用原生通用详情，例如缺少退出状态的命令、缺少文件总行数的非首行读取窗口；不补造成功退出码或文件总行数。ACP 工具的 Inspect 打开已记录的协议详情，不跳转到不存在的宿主工具事件。

## 数据兼容与展示成本

审批中的命令详情只从请求自身或可按调用 ID 关联的更新中取得；无法关联时明确提示详情缺失，不借用其他调用的命令。普通审批只传递 Agent 提供的操作标题、命令和参数，等待状态、按钮等由原生界面按页面语言展示。缺失命令警告及通用问答中的适配器文案仍使用 DSH 已保存的语言设置；未保存时回退英文，因为宿主无法读取每个浏览器的自动检测结果。通用表单优先显示 Agent 提供的标题和选项名称，命令保持原文。主会话中 Codex 的工具授权范围显示本地化文案，选项仍准确回传为仅本次、本会话或持续授权；原生审批卡不支持后两种范围，因此使用原生问答组件，不合并或弱化权限。当前 DSH 工具桥确认身份后会显示原生工具名，其他请求保留原始上下文。 DSH 禁止从仍归属于父会话的子会话直接发起问答。对于已核实当前工具身份、且表单只有授权范围并提供“仅本次”的 Codex 请求，子会话改用原生一次性审批，仍归属于该成员，可在主会话处理；不会批准本会话或持续授权，也不会把普通问题或其他表单字段转换为审批。

输入栏保留独立的会话设置入口：第一级显示设置项与当前值，第二级显示选项、说明和选中状态，选择后自动收起。模式等选项来自当前 Agent；模型与推理强度仍在原生模型选择器中，上下文用量和费用保留在菜单底部。输入栏、团队成员模式和批量模式共用同一个菜单组件；团队仅传入模式选项，模型仍由模型控件处理。只读状态禁用修改，休眠成员仍可保存下次生效的模式，不另建一套只读界面。

新建文件的原子创建需要目标文件系统支持硬链接；不支持时返回写入错误，不退回可能覆盖其他文件的写法。

成员模型选择使用按会话与 binding 保存的 Sidecar 表，旧数据库自动建表，无需清理数据。原生 Teams 名单的模型文案仍由宿主维护，未修改其展示。当前 ACP 模型目录没有逐模型图片能力声明，延续既有 ACP 图片能力校验；若未来声明不同模型的图片能力，需要同步适配宿主 continuation 仍读取初始模型的图片准入路径。

活动顺序使用可空的 `content_index` 列，打开旧数据库时自动添加。旧记录缺少内容位置，继续原有分组展示，不按时间戳猜测或重写；无需清理本地数据。

展示数据使用可空 `display_detail` 列，单独存储归一化的完整 Diff 与计划，不再把截断的诊断 JSON 当成原文件内容。单个展示对象的上限为 2 MiB；超限时整项标明不可用，不把文件截断后制造虚假的 Diff。旧数据已截断的部分无法恢复，也不会再送入 DiffBlock。活动分页与实时流对超过 16,384 字符的详情仅发送摘要，展开时通过同一会话权限检查读取准确修订号的完整内容，再交给原生组件。加载失败可重试，旧响应不会覆盖新修订；小详情保持即时展示。此调整减少传输与首屏渲染成本，不减少完整记录的存储成本。

ACP 计划被投影到已有 `todos` 状态和 DSH 原生计划面板，同时保留历史快照；仅当宿主已注册该投影时才写入 `todo/write`。prompt 返回、失败或取消均不会把尚未完成的计划自动标成完成。外部计划状态仅作观察，不调用 `todo_write`、不强制采用原生工具的单任务/多任务规划策略。

计划投影只使用可选的官方 `dsh-tool-todo` 类型声明，不在运行时加载或启用该插件。

目录预填与宿主 runtime 行为分别维护，共用浏览器安全的配置身份契约。命令、参数与环境默认值取自 registry 快照，仅补充已知的 Devin/Kimi binary PATH 命令和目录未提供的登录说明。手写 runtime descriptor 已删除，专有兼容规则和 Devin 启动配置分别由小型兼容函数与启动适配入口承接；通用会话流程不再判断厂商。旧绑定中的 `descriptorId` 保留字段名及原值，仅作为 runtime 身份存储，避免重构改变已有会话指纹。`catalogId` 仅关联目录元数据，不授予特殊运行行为，不参与启动指纹。旧配置继续按原有 runtime / ID 规则查目录；从目录添加的配置即使自定义 ID，仍保留目录关联。

恢复诊断区分当前连接复用、实际 `session/resume` 和实际 `session/load`。旧记录缺少方式字段时保留未知，不根据零条回放猜测。回放仍仅作诊断，不覆盖 DSH 可见历史。


每次处理 ACP `session/request_permission` 的工具桥判断时，诊断记录保留规范工具名、匹配来源及不自动处理的原因，不保存能力名称、桥接地址或授权选项 ID。该记录描述判断时的状态；执行前仍重新检查连接和请求有效性。自动判断符合条件不代表工具已经执行成功。可以在 ACP 诊断的“操作”中复制所选记录及适配器版本。

Devin 请求若带有当前 DSH 连接的能力前缀、但工具名不在该连接公布的清单中，适配器直接拒绝并记录 `invalid-tool-name`，不再让用户审批一个无法执行的调用。Agent 可以随后重新发出正确请求；是否重试由 Agent 决定。适配器不会截断工具名中的参数片段、补造参数或执行错误调用。其他连接、无法归属的请求及合法普通工具仍按原审批流程处理。

## DSH 工具桥

宿主为当前会话提供 `present` 时，Agent 会自动获得该工具，用于交付文档、表格等本地文件，无需额外 ACP 配置。文件必须位于 Host 可访问的 Session 文件系统中。Agent 调用后，由 DSH 原生文件卡片和预览展示；无需单独的 ACP 文件卡片。只写一个文件路径不会自动产生交付卡片；预览打开当前源文件，不保存内容快照。

工具桥按 DSH 原生会话作用域自动发现工具，无需开启 Teams；插件新增的可见工具也会自动接入。调用使用 DSH `tools.execute`，复用参数检查、执行前/后插件钩子和工具自身规则。工具移除或作用域收窄后，旧连接立即失效；新增工具在下一次 ACP 连接初始化时生效。Teams 协调工具仅向原生成员提供，其审批特例不会扩展到普通插件工具。已删除手填工具配置栏；旧 `hostTools` 字段被忽略，不影响旧会话恢复，编辑保存时移除。

工具桥增加一层 MCP 调用，Agent 自带工具和 DSH 同类工具可能同时存在；选择 DSH 工具才会进入宿主执行链。它不把外部 Agent 的 shell、文件操作或模型调用重新执行一遍，也不完整恢复 DSH 模型循环的各个切面：依赖原生模型调用、PTC 专用调用身份或 loop 控制权的插件仍需单独适配。`concludesTurn` 只能传递为结束请求，由外部 Agent 响应，不能保证强制结束。原生图片结果通过附件服务及容量校验转换；文件附件目前只有原生文件说明，没有执行环境路径映射时会明确说明不可读；无法表示的输出明确提示，不静默丢弃。Agent 自身的权限与上下文管理继续由 Agent 负责。

验证范围与复现方法见 [E2E 指南](../test/e2e/README.md)，发布流程见 [发布指南](releasing.md)。

## 会话与展示

本版本仅支持 DSH `0.1.7-alpha.2`。主区域导航使用 `uiWorkspace`，成员与外部子会话使用原生 `subagentchat` 资源侧栏；DSH 负责引用生命周期、历史加载和恢复。外部投影保持只读，Teams 成员沿用原生续聊规则。模型切换观察各个已打开的 Session，诊断 Tab 只由主区域会话决定，避免侧栏会话争抢全局入口。

主会话审批从原生 `sessionStatus.pendingInteraction` 读取成员的原始请求。批量操作仍逐项核验成员归属和请求身份，不把后来到达的请求加入已发起的批次。

原生 continuable 子 Agent 默认最多 8 个活动实例；创建和冷恢复都受其限制。Team 成员上限仍是另一项独立设置。通用委派工具默认深度改为 1；外部 Agent 内部的子任务不由这些宿主设置完整控制。

原生 turn 文件变更卡片依赖修改前快照及 DSH 工具事件，不能保证捕获 ACP 内部文件操作。目前继续将 ACP 提供的真实文件差异归一化后交给原生 `DiffBlock`，不伪造原生工具执行记录。ACP 上下文用量也继续使用 Agent 报告的 used/size；原生 context meter 的 DSH 请求估算不能等价替换它。

外部只读子会话通过宿主子会话目录发布，并保留父会话归属。恢复已有 V3 投影时先校验原始摘要，再使用宿主 V3 → V4 迁移器；不支持的历史格式或缺失内容保留原记录，不伪造迁移。Agent 配置使用原生插件配置表单与修订检查，从旧设置文件导入时不覆盖当前已配置的 Agent 列表（包括空列表）。
