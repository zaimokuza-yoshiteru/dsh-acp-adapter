# 原生复用与保留边界

本轮按 UI、运行时、构建与依赖四个模块核查；兼容目标以 `package.json` 的 `engines.dsh` 为准。

本次兼容基线为已发布 DSH `0.1.6-alpha.1`（`0a15e36e7f82`）。2026-09-16 抓取的上游最新提交为 `0d1f50007f9b`；相对基线，agent-loop、llm 与 ui-conversation 目录没有新增差异。未通过移动 reference checkout 或混用未发布包来绕开版本约束。

| 范围 | 实现与边界 |
| --- | --- |
| 会话执行状态 | ACP 只定义执行事实的增量 fold，DSH `sessionProjections` 负责驱动、缓存与恢复；输入准入、历史判定、开放轮次和 fork 标记共用这一状态。提交水位直接读取 `Session.seq`，权限读取宿主 `permissions` 投影；运行时释放仍匹配原始 Session 对象，避免读取封装影响生命周期。 |
| 运行中输入 | 使用原生 inbox、pre-step 和消息持久化。默认仅取消 ACP 执行并等待确认，原生 loop 接续新 step；协商支持原子注入时，一个 ACP prompt 可跨原生 step 输出。拒绝输入、切换路由和结束 turn 时回收挂起执行，不公开或调用私有 inbox.claim。 |
| 对话与活动 | ACP 通知归一化为 DSH stream 和活动数据；活动首次出现的内容边界持久化到 Sidecar，后续状态更新不改变位置。通过公开插槽组合已注册的原生 assistant renderer，按序穿插原生工具详情组件；不复制 Markdown、思考或图片组件，也不伪造宿主工具调用。原生会话直接委托原 renderer；旧活动或不兼容的第三方 renderer 保留独立活动展示。 |
| 客户端类型与构建 | React 使用官方开发类型，运行时仍由宿主提供；构建和验证共用平台模块清单，reference 门禁与上游源码比对。 |
| RPC 元数据 | 继续使用精确 npm 版本的官方 Typert generator。生成后为严格 codec 增加返回同一校验器的 `create()`，兼容 alpha.1 的 `schema` 消费方式和上游 `e459e3263733` 引入的 factory 消费方式；Host 与 Remote 两端同时处理，不依赖桌面补丁，不放宽校验。校验器仍提前构造，尚未获得延迟创建的启动性能收益。升级到官方 factory generator 并调整最低宿主版本时，应删除这段构建适配。 |
| 审批与成员模式 | 原生审批负责当前请求，团队摘要转发原始审批；仅本次允许、拒绝和逐 Agent 类型批量模式规则保留。原生权限选择器不替换。 |
| 进程与期限 | 继续复用宿主 subprocess 与 timeout；ACP 保留协议连接、取消收敛和错误分类。 |
| 文件写入 | 保留字节内容、拒绝最终符号链接、哈希审计和并发校验。宿主文本写入会规范化换行，不能直接等价替换。 |
| 成员模型 | ACP 主会话面板提供同一 profile 内的成员模型选择；公开 `installModelSelection` 同时驱动提示词、请求配置和模型变更说明，`llm.resolveCallConfig` 使用新模型的默认思考配置。选择绑定原 ACP 会话，休眠恢复时重新应用，不写全局默认。运行中或待审批时不可修改。 |
| Teams 通信 | 保留 ACP 到宿主 Teams 的 MCP server bridge；宿主 MCP client 和无人值守 ACP 子任务不能承担这一角色。 |
| 本地数据 | Sidecar 继续负责绑定、dispatch 状态与诊断事务；宿主 Session 日志和通用 KV 不提供等价事务。新增执行投影是可重建缓存，不修改 Session 格式或 Sidecar schema，无需清理历史数据；旧会话首次使用可能需要从已有事件重建投影。 |

已删除手工 React 类型声明、重复历史扫描以及仅测试调用的 journal 包装方法；活动测试直接覆盖生产使用的 replace/append 接口。未发现可以直接删除的整份运行时模块。动态加载的 stdio MCP bridge、历史 payload 测试夹具以及子进程测试入口均有实际用途。上游公开接口不能保持现有行为时，保留必要适配，避免引入另一套私有宿主依赖。

本轮验证结果记录在 [回归记录](../test/e2e/REGRESSION.md)。

成员模型选择新增一张按会话与 binding 保存的小型 Sidecar 表，旧数据库自动建表，无需清理数据。原生 Teams 名单的模型文案仍由宿主维护，未修改其展示。当前 ACP 模型目录没有逐模型图片能力声明，延续既有 ACP 图片能力校验；若未来声明不同模型的图片能力，需要同步适配宿主 continuation 仍读取初始模型的图片准入路径。

活动顺序新增可空的 `content_index` 列，打开旧数据库时自动添加。旧记录缺少内容位置，继续原有分组展示，不按时间戳猜测或重写；无需清理本地数据。

2026-09-16 的展示修复新增可空 `display_detail` 列，单独存储归一化的完整 Diff 与计划，不再把截断的诊断 JSON 当成原文件内容。单个展示对象的上限为 2 MiB；超限时整项标明不可用，不把文件截断后制造虚假的 Diff。旧数据已截断的部分无法恢复，也不会再送入 DiffBlock。完整详情随活动分页传输，尚未实现按展开加载，因此包含大量大文件 Diff 的会话会增加存储、传输及渲染开销。

ACP 计划被投影到已有 `todos` 状态和 DSH 原生计划面板，同时保留历史快照；仅当宿主已注册该投影时才写入 `todo/write`。prompt 返回、失败或取消均不会把尚未完成的计划自动标成完成。外部计划状态仅作观察，不调用 `todo_write`、不强制采用原生工具的单任务/多任务规划策略。

可选 `hostTools` 名单扩展现有 MCP 桥，无需开启 Teams。调用使用 DSH `tools.execute`，复用参数检查、执行前/后插件钩子和工具自身规则。MCP 连接只暴露当前 Agent 可见且明确选择的工具，工具失效或作用域变更会拒绝旧连接；未安装的工具会明确报错。Teams 原有协调工具的审批特例不会扩展到普通插件工具。名单参与会话启动指纹，修改后需要新建会话，避免旧连接继续使用过期能力。

工具桥增加一层 MCP 调用；重叠工具会增加 Agent 选错工具的可能，所以默认空名单。它不把外部 Agent 的 shell、文件操作或模型调用重新执行一遍，也不完整恢复 DSH 模型循环的各个切面：依赖原生模型调用、PTC 专用调用身份或 loop 控制权的插件仍需单独适配。`concludesTurn` 只能传递为结束请求，由外部 Agent 响应，不能保证强制结束。原生图片结果通过附件服务及容量校验转换；文件附件目前只有原生文件说明，没有执行环境路径映射时会明确说明不可读；无法表示的输出明确提示，不静默丢弃。Agent 自身的权限与上下文管理继续由 Agent 负责。

消息排序并非 DSH 0.1.6 新增的 ACP 专用 API。`conversation.chat.node` 的原生 `assistant-step` 注册、`slots.entriesOfSlot()` / 优先级和 Location data source 在 `dsh-v0.1.5-rc.2` 已存在；相关通用机制可追溯到 `c7d8e32aec`、`56a4d51d2c`、`577f0cf7d9`。本次新增的是插件的持久化顺序和渲染组合适配，不修改宿主，也不意味着旧宿主版本已经通过本插件当前依赖组合的兼容验证。

2026-09-16 的代码清理合并了 Host 与 Client 的纯 Diff 字段识别和 hostTools 名称校验，共享代码保持无依赖。计划投影使用可选的官方 `dsh-tool-todo` 类型声明，消除事件与状态键的强制断言，不在运行时加载或启用该插件。删除未调用的测试故障分支；动态入口和旧数据库兼容读取继续保留。
