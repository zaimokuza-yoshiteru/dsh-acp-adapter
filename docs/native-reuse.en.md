# Native reuse and compatibility boundaries

[中文](native-reuse.md)

The supported DSH version is defined by `engines.dsh` in `package.json` and the pinned official npm dependencies. Upstream source is used only as browser-test scaffolding; it does not replace release dependencies.

DSH owns input admission, host extensions and native presentation. The Agent owns its model loop, permission decisions and context management. The adapter normalizes protocol data before passing it to native components. It retains adaptation where public upstream interfaces cannot preserve the required behavior.

| Area | Reuse and limitations |
| --- | --- |
| Session execution state | ACP supplies an incremental projection of execution facts; DSH `sessionProjections` drives, caches and restores it. Input admission, history checks, open turns and fork markers share that state. Commit positions use `Session.seq`, permission state uses the host projection, and runtime cleanup still checks the original Session object's identity. |
| Input during execution | Uses the native inbox, pre-step hooks and message persistence. By default, the adapter cancels ACP execution, waits for acknowledgement and lets the native loop continue with a new step. Negotiated atomic injection allows one ACP prompt to span native steps. Rejected input, route switches and turn endings release suspended execution without using private inbox APIs. |
| Conversation and activity | ACP events become DSH stream and activity data. Initial content positions persist in the Sidecar and remain stable across status updates. Public slots compose the registered native assistant renderer with native tool details in order. Markdown, thinking and image components are reused, and external tool calls are not presented as host executions. Native sessions delegate to the original renderer. Older activity and incompatible third-party renderers retain separate activity presentation. |
| Client types and builds | Uses official React development types and the host's runtime. Build and verification share a platform-module list, checked against the upstream reference. |
| RPC metadata | Uses the pinned official Typert generator. A build adaptation adds `create()` returning the same strict validator, supporting both alpha.1's `schema` consumers and the factory consumers introduced upstream in `e459e3263733`. This applies to Host and Remote, needs no desktop patch and does not relax validation. Validators are still constructed eagerly. Remove the adaptation when adopting the official factory generator and raising the minimum host version. |
| Approvals and member modes | Native approval handles the current request; team summaries forward the original approval. Allow-once, rejection and batch modes grouped by Agent type retain their scope. The native permission selector is unchanged. |
| Processes and deadlines | Reuses host subprocess and timeout services. ACP retains protocol connections, cancellation settlement and error classification. |
| File writes | Preserves bytes, rejects final symlink targets and retains hash auditing and concurrency checks. If another writer creates a new target first, the write reports a conflict and preserves that file. Existing files still use a pre-write hash check, which is not a cross-process transaction. The host text writer normalizes line endings and cannot replace this path equivalently. |
| Member models | The main ACP session panel selects member models within the same profile. Public `installModelSelection` updates prompts, request configuration and model-change notices; `llm.resolveCallConfig` supplies the new model's reasoning defaults. Selection stays with the original ACP session, is reapplied after dormancy and does not change global defaults. Changes are disabled while running or awaiting approval. |
| Teams communication | Retains the ACP-to-host Teams MCP server bridge. Neither the host MCP client nor unattended ACP subtasks provide this role. |
| Local data | The Sidecar owns bindings, dispatch state and diagnostic transactions. Host Session logs and generic KV storage do not provide equivalent transactions. Execution projections are rebuildable caches; Session format and Sidecar schema are unchanged. Existing sessions may rebuild a projection from their events on first use; no history cleanup is needed. |

## Data compatibility and display costs

Approval commands come only from the request itself or updates correlated by tool-call ID. When correlation is unavailable, the card explicitly reports missing details instead of borrowing another call's command. Adapter-generated approval text follows DSH's saved Chinese or English language preference. Without a saved preference it uses English, because the host cannot read browser language detection. Agent-provided titles, options and commands retain their original text.

Atomic creation of new files requires a filesystem that supports hard links. Unsupported filesystems return a write error rather than falling back to an operation that could overwrite another file.

Member-model selections are stored per session and binding in the Sidecar. Existing databases gain the table automatically. Native Teams roster model labels remain host-owned. The ACP model catalog currently lacks per-model image capabilities, so existing ACP image admission applies. Supporting such declarations later would also require adapting native continuations, which still check the initial model's image capability.

Activity order uses a nullable `content_index` column added automatically to old databases. Records without positions retain their previous grouped display; positions are neither guessed from timestamps nor rewritten. No local-data cleanup is required.

Normalized, complete diffs and plans use a separate nullable `display_detail` column. Truncated diagnostic JSON is no longer treated as original file content. Each display object is limited to 2 MiB; oversized objects are marked unavailable as a whole rather than producing a misleading partial diff. Previously truncated content cannot be recovered and is not sent to DiffBlock. Activity pages and live streams send summaries for details over 16,384 characters. Expanding a detail loads the full revision under the same session permission checks and passes it to the native component. Failed loads can be retried, stale responses cannot replace newer revisions, and small details remain immediate. This reduces transfer and initial rendering costs, not storage costs.

ACP plans project into existing `todos` state and the native plan panel while retaining historical snapshots. The adapter writes `todo/write` only when the host has registered the projection. Prompt completion, failure or cancellation does not mark unfinished tasks complete. External plans remain observational: the adapter does not call `todo_write` or impose the native tool's planning policy. Only optional official `dsh-tool-todo` type declarations are used; the adapter does not load or enable that plugin at runtime.

Catalog defaults and host runtime behavior are maintained separately with a shared browser-safe configuration identity contract. Commands, arguments and environment defaults come from the registry snapshot, supplemented by known Devin/Kimi PATH commands and missing login guidance. Small compatibility functions and a Devin launch adapter replace handwritten runtime descriptors. The old binding field `descriptorId` keeps its name and value as runtime identity, preserving existing session fingerprints. `catalogId` links catalog metadata only; it grants no special behavior and is excluded from launch fingerprints. Existing configurations retain runtime/ID-based catalog lookup, and newly added catalog profiles keep their association even with custom IDs.

Recovery diagnostics distinguish reuse of the current connection, actual `session/resume` and actual `session/load`. Older records remain unknown rather than inferring a method from zero replay events. Replay remains diagnostic and does not replace visible DSH history.

## DSH tool bridge

The optional `hostTools` list extends the existing MCP bridge without requiring Teams. Calls use DSH `tools.execute`, including argument validation, before/after plugin hooks and each tool's rules. Connections expose only explicitly selected tools visible to the current Agent. Removed tools or changed scopes invalidate old connections; unavailable tools produce explicit errors. Approval exceptions for Teams coordination tools do not apply to ordinary plugin tools. The list participates in the session launch fingerprint, so start a new session after changing it.

The bridge adds an MCP call. Overlapping tools can cause the Agent to choose the wrong tool, so the list is empty by default. It does not repeat the external Agent's shell, file or model execution, and it cannot restore every DSH model-loop extension point. Plugins requiring native model calls, PTC-specific call identities or loop control still need separate adaptation. `concludesTurn` is forwarded as a request; the external Agent decides how to respond, so forced termination is not guaranteed. Native image results pass through attachment services and size validation. File attachments currently carry native file descriptions; without execution-environment path mapping they are explicitly marked unreadable. Unrepresentable output is reported rather than silently dropped. The Agent continues to own its permissions and context management.
