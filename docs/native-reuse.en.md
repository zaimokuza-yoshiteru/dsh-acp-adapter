# Native reuse and compatibility boundaries

[中文](native-reuse.md)

The compatibility target is the exact DSH version and official npm dependencies pinned in `package.json`; upstream source is only a test scaffold. DSH owns input admission, host tools, and native presentation. An external Agent owns its model loop, native tool permissions, and private context. The adapter translates protocol data between them and retains continuity, permission, and persistence behavior that public host interfaces cannot yet provide equivalently.

## Sessions and input

DSH's native inbox, pre-step hooks, and Session message persistence admit input. The adapter sends only the current admitted input over ACP; it does not rebuild AgentLoop or replay ordinary user history. During an active prompt, injection is possible only when the current ACP connection explicitly advertises safe injection; other handoffs cancel the old prompt, wait for its result and approvals to settle, then continue in the same Agent session. Native Agent CLI capabilities cannot replace the connection's advertisement. Effective DSH runtime context and a skill catalog may be passed to the Agent, but they do not install Agent-private skills or grant tools or permissions. Main model, reasoning, and search choices use native DSH selectors; Agent modes and pending member models remain bound to their ACP sessions rather than changing global defaults.

The ACP adapter normalizes execution facts for DSH `sessionProjections` to drive and restore; the projection is a rebuildable cache. The Sidecar still owns ACP bindings, dispatch state, and diagnostic transactions. Native Session logs and generic KV storage do not provide equivalent transactions. Existing history is neither rewritten nor cleared when the projection changes. An explicit blank rebind resends only AGENTS instructions in the current effective Host projection, preserving order and replacement/removal semantics; normal continuation and restoration do not resend them.

If the remote terminal result is confirmed but local persistence is pending, the current Host settles it before later input and does not replay completed tools; that pending state is not guaranteed to survive a Host restart. If remote acceptance remains uncertain, recovery stays gated: the adapter neither resends automatically nor hides lost context behind a blank session. Transient reads may retry; stable errors must appear as unavailable rather than empty data. DSH's native session-log ZIP does not include ACP Sidecar records. See the [README troubleshooting section](../README.en.md#troubleshooting-and-feedback) for export and sharing.

## Tools, permissions, and optional capabilities

Qwen Code background and scheduled turns are adopted through native jobs and AgentLoop. A background completion notice wakes the Agent and adopts the turn Qwen has already started; other inputs admitted in the same step are sent in order after that turn has a confirmed terminal response. Unannounced scheduled turns use negotiated active-work snapshots to confirm completion; model usage or silence is insufficient. An unconfirmed Stop closes the connection and retains an unknown outcome. Qwen questions use the native question panel, and private extensions apply only to an identified Qwen Agent. See the [E2E guide](../test/e2e/README.md) for separate fixture and real-Agent coverage.

The bridge exposes only tools assembled by DSH for the current admitted request that remain active in the session scope. It follows the Host's native or PTC mode. Calls use native `tools.execute`, including argument checks, hooks, and tool rules; removed tools or narrowed scope revoke old connections. Requests confirmed as coming from this bridge but naming unregistered tools are rejected instead of offering approval for an unexecutable call. The Agent's own shell, file, and model calls remain Agent-owned and do not become DSH tool events through the bridge; plugins requiring native model calls, PTC-internal call identity, or loop control still need separate adaptation. The Host MCP client and one-shot external subtasks cannot replace an interactive ACP session or its Teams communication bridge.

ACP Auto/Ask controls whether DSH tool requests require additional human approval; the Agent still owns its native permissions. Auto/Ask is not native Auto Review's LLM risk assessment. Team members inherit their authenticated Lead's policy live, while an ordinary fork saves an independent policy on its first ACP initialization. When native approval cards cannot express an Agent's session-wide or persistent authorization choices, the adapter retains an explicit option question instead of silently reducing the grant to one use or approving it by default. If a child session cannot ask a question directly, only a verified tool request whose options concern authorization scope and include one-use approval may become native one-use approval. Native Auto Review, automatic titles, and `/compact` auxiliary model calls currently lack the ACP admission identity required for ordinary prompts, so equivalent support cannot be promised. The [open experience gaps](../.agents/notes/proposed/2026-10-11-acp-native-experience-gaps.md) record the conditions for follow-up.

ACP file writes preserve bytes, reject final symlinks, and retain concurrent hash and new-file conflict checks. Host text writes normalize content and are not an equivalent replacement. Before native Worktree or `working_directory` changes the directory, the adapter must establish support for a context-preserving `session/fork`. Supported Agents transfer the binding after the old execution and Host tools settle; unsupported Agents are rejected before Git or directory side effects. A known pending handoff can continue later, while an uncertain dispatched result remains under explicit recovery.

User-facing official optional bundles are enabled through native DSH Plugins; the adapter adds no second switch. Installation, code import, service activation, and availability in the current session are distinct states. The Teams UI entry follows its official contribution when enabled or disabled. ACP image capability reaches native tools only when the current caller, Session, runtime generation, confirmed model, and live connection match; unknown capability is not mislabeled text-only. The official `appendPluginRecord` write surface does not include this plugin and cannot replace the Sidecar.

## Presentation and observability limits

ACP notifications are normalized before native DSH Assistant, tool tree, Diff, plan, and process-group presentation; native sessions retain their renderer. If an exit status, file line count, or historical content position is absent, the UI shows known facts or generic details instead of inventing numbers, order, or Host execution events. Truncated diagnostics cannot become a complete Diff. ACP plans are projected for observation only; the adapter does not call `todo_write` in response or force unfinished tasks to completion.

Current public Host interfaces cannot produce full native Session tool events or workspace-change events for every ACP tool call, nor reliably capture the Agent's internal file operations. Actual ACP diffs may be shown through native DiffBlock, while context usage remains Agent-reported. External subtasks become read-only child sessions only after source, identity, and child-terminal evidence is verified; a result preview does not claim to be complete private history. Unrepresentable attachments or output are explained rather than silently dropped.
