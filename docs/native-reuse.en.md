# Native reuse and compatibility boundaries

[中文](native-reuse.md)

The supported DSH version is defined by `engines.dsh` in `package.json` and the pinned official npm dependencies. Upstream source is used only as browser-test scaffolding; it does not replace release dependencies.

DSH owns input admission, host extensions and native presentation. The Agent owns its model loop, permissions for its own tools and context management; DSH tool requests follow the session policy or native approval. The adapter normalizes protocol data before passing it to native components. It retains adaptation where public upstream interfaces cannot preserve the required behavior.

The adapter does not invent successful exits or file line counts. Inspect opens the recorded ACP payload instead of linking to a nonexistent host tool event.

## Result settlement and diagnostic boundaries

When the remote terminal result is confirmed but local result persistence temporarily fails, the adapter retries with backoff in the current Host instance. A later prompt waits for local settlement; completed tools are not replayed. Stopping the currently displayed turn does not stop the background save retry. Pending settlement is held in memory and is not guaranteed to survive process exit. This ordinary transient path does not require manual recovery; an unknown remote outcome continues to use recovery status and must remain distinct.

ACP Diagnostics builds its summary with bounded paging and an allowlist of fields. Recovery status is read separately, so the sections are not a cross-table atomic snapshot. DSH's native session-log ZIP does not include ACP Sidecar records. See the [quick-start troubleshooting section](../README.en.md#troubleshooting-and-feedback) for export and sharing steps.

Transient recovery-status and Team-roster read failures reconnect or retry automatically. Stable permission, configuration or protocol errors are shown as unavailable; failed reads are not presented as an empty recovery state or roster. Rereading the roster never approves or rejects requests automatically; native approval remains a user decision.

## Data compatibility and display costs

RC team rosters come from the shared `agentTeam` projection, with running state supplied by native session status. The adapter no longer calls the removed Teams Remote or polls the roster. ACP member modes and current/pending models still use ownership-checked reads and writes. A failed projection cannot authorize actions through residual roster data, and another team's pending requests do not appear in the current team's approval card. Migration does not rewrite existing team journals.

Approval commands come only from the request itself or updates correlated by tool-call ID. When correlation is unavailable, the card explicitly reports missing details instead of borrowing another call's command. Ordinary approvals carry only Agent-supplied operation titles, commands and arguments; the native UI localizes waiting states and buttons. Missing-command warnings and adapter text in generic questions still follow DSH's saved language preference, falling back to English when unset because the host cannot read each browser's detected language. Generic forms display Agent-provided titles and option names; commands remain unchanged. In a root session, Codex tool approval scopes use localized labels and still return the exact once, session or persistent scope. Since the native approval card cannot represent the latter two, these requests use native questions without collapsing permission scopes. The current DSH bridge displays a native tool name only after verifying its identity; other requests retain their original context. DSH rejects direct questions from children still owned by another live session. A Codex child request can instead use native one-time approval only when the current tool identity is verified and the form contains only an approval scope offering once. Approval stays owned by that member and can be handled from the lead; session or persistent permission is never granted this way, and ordinary questions or additional form fields are not converted.

The input row keeps an independent session-settings entry. Its first level shows each setting and current value; the second shows choices, descriptions and selection state, then closes on selection. Modes and other options come from the current Agent. Models, reasoning and search use the native selector, while DSH owns the model catalog and switching logic. Context usage and cost stay in the menu footer. The input row, individual member modes and batch modes share one menu component. Teams supply only mode choices and retain their separate model control. Read-only state disables writes; dormant members can still save modes for their next request, using the same presentation.

Atomic creation of new files requires a filesystem that supports hard links. Unsupported filesystems return a write error rather than falling back to an operation that could overwrite another file.

Member-model selections are stored per session and binding in the Sidecar. Existing databases gain the table automatically. Native Teams roster model labels remain host-owned. The ACP model catalog currently lacks per-model image capabilities, so existing ACP image admission applies. Supporting such declarations later would also require adapting native continuations, which still check the initial model's image capability.

Activity order uses a nullable `content_index` column added automatically to old databases. Records without positions retain their previous grouped display; positions are neither guessed from timestamps nor rewritten. No local-data cleanup is required.

Normalized, complete diffs and plans use a separate nullable `display_detail` column. Truncated diagnostic JSON is no longer treated as original file content. Each display object is limited to 2 MiB; oversized objects are marked unavailable as a whole rather than producing a misleading partial diff. Previously truncated content cannot be recovered and is not sent to DiffBlock. Activity pages and live streams send summaries for details over 16,384 characters. Expanding a detail loads the full revision under the same session permission checks and passes it to the native component. Failed loads can be retried, stale responses cannot replace newer revisions, and small details remain immediate. This reduces transfer and initial rendering costs, not storage costs.

ACP plans project into existing `todos` state and the native plan panel while retaining historical snapshots. The adapter writes `todo/write` only when the host has registered the projection. Prompt completion, failure or cancellation does not mark unfinished tasks complete. External plans remain observational: the adapter does not call `todo_write` or impose the native tool's planning policy. Only optional official `dsh-tool-todo` type declarations are used; the adapter does not load or enable that plugin at runtime.

Catalog defaults and host runtime behavior are maintained separately with a shared browser-safe configuration identity contract. Commands, arguments and environment defaults come from the registry snapshot, supplemented by known Devin/Kimi PATH commands and missing login guidance. Small compatibility functions and a Devin launch adapter replace handwritten runtime descriptors. The old binding field `descriptorId` keeps its name and value as runtime identity, preserving existing session fingerprints. `catalogId` links catalog metadata only; it grants no special behavior and is excluded from launch fingerprints. Existing configurations retain runtime/ID-based catalog lookup, and newly added catalog profiles keep their association even with custom IDs.

The standard CodeBuddy CLI uses an explicit `codebuddy` runtime and the `codebuddy --acp` command. The bridge correlates its Host tool permission requests with the tools registered for that connection; it does not infer identity from a bare tool name or `catalogId`. Existing custom profiles are not reclassified automatically. This runtime does not cover the WorkBuddy desktop app. Saved Agent mode snapshots normalize display metadata: each mode description is limited to 1,024 characters, and the current mode is retained preferentially within the mode-count and total serialized-length budgets. The existing total budget is unchanged.

Antigravity uses the explicit `antigravity` runtime and the official raw ACP server. Only registered tools whose identity matches the current DSH MCP connection execute through the bridge; other native permission requests remain subject to DSH permission validation and approval. Fixed-option `request_permission` questions use the plugin's native card and require an explicit selection and submission. There is no free-text answer or automatic approval. After an external Stop, a subsequent failure is presented as cancelled only for a previously observed running tool call when the external cancellation signal is active; the original provider result remains available. Real verification is limited to macOS, the official raw ACP server 1.3.0, `gemini-3.8-flash-low`, and the scenarios listed in the E2E guide. Antigravity app authentication is separate from the ACP account and is not migrated by the plugin. The wrapper, Teams, Windows and the full OAuth first-run flow are not verified.

When the explicit CodeBuddy runtime returns a confirmed cancelled terminal result, including rejection of a native tool request, the adapter remembers that result and reloads the same bound ACP session before the next input. It does not resubmit the cancelled prompt or require manual recovery for this normal refresh; refreshing may add startup wait time. This behavior requires a confirmed cancellation and does not apply when the remote outcome is unknown or Host calls remain unfinished.

Recovery diagnostics distinguish reuse of the current connection, actual `session/resume` and actual `session/load`. Older records remain unknown rather than inferring a method from zero replay events. Replay remains diagnostic and does not replace visible DSH history.

Each bridge check for ACP `session/request_permission` records the canonical tool name, identity source and reason for not handling it automatically, excluding capability names, bridge addresses and permission option IDs. The record describes the check at that moment; connection and prompt validity are checked again before answering. An eligible check does not mean the tool executed successfully. The Operations view in ACP Diagnostics can copy the selected record with the adapter version.

## DSH tool bridge

When the Host directly offers `present` to the current model request, the Agent receives it automatically for local document, spreadsheet or other file deliveries. No extra ACP configuration is needed. Files must be accessible through the Session filesystem. Calls produce DSH's native file cards and previews without a separate ACP file UI. Mentioning a path alone does not produce a delivery card; previews open the current source file rather than a saved content snapshot.

The bridge intersects the tools DSH assembled for the current admitted request with the active native definitions in that session scope, without requiring Teams. New plugin tools are included when the host offers them to the model. PTC mode exposes only `run_code` over MCP; `both` follows the combined host directory. The bridge never fabricates a parent call to bypass execution limits. Calls use DSH `tools.execute`, including argument validation, before/after plugin hooks and each tool's rules. Removal or narrowed scope revokes old connections immediately; directory changes between requests refresh the connection and restore the existing remote binding. Missing tool declarations never fall back to the full registry. Team coordination tools are exposed only to native members; all DSH tools follow the session's Auto or Ask policy. The manual tool field is removed. Retired `hostTools` values are ignored without blocking session restoration and are removed on editor save.

The bridge preserves native DSH tool names, such as `send_message`. Each connection binds the caller Agent; native Teams resolves `target` within that caller’s Team. Separate Teams may use identical member and tool names. The current connection verifies tool identity, and the session's Auto or Ask policy applies to all DSH tools, including Teams tools. After registration, Devin’s effective `dsh` entry is checked for an unexpected command or an override that hardcodes a session address.

MCP TypeScript SDK v2 cancellation notifications reach active DSH tool calls and enter host execution through the ToolRuntime cancellation signal. Cancellation applies to the current call; the adapter does not turn it into an automatic retry.

The bridge adds an MCP call. Agent-provided tools and equivalent DSH tools may coexist; only calls through DSH tools enter the host pipeline. It does not repeat the external Agent's shell, file or model execution, and it cannot restore every DSH model-loop extension point. Plugins requiring native model calls, PTC-specific call identities or loop control still need separate adaptation. `concludesTurn` is forwarded as a request; the external Agent decides how to respond, so forced termination is not guaranteed. Native image results pass through attachment services and size validation. File attachments currently carry native file descriptions; without execution-environment path mapping they are explicitly marked unreadable. Unrepresentable output is reported rather than silently dropped. The Agent continues to own its permissions and context management.

A request identified as belonging to the current DSH MCP server but naming an unregistered tool is rejected with `invalid-tool-name`; users are not asked to approve an unexecutable call. The adapter does not strip argument fragments, invent arguments or execute malformed calls. Unidentified requests retain their normal approval flow; valid DSH tools follow the session policy.

For verification and reproduction, see the [E2E guide](../test/e2e/README.md) (Chinese); for publishing, see the [release guide](releasing.md) (Chinese).

## Sessions and presentation

Main-area navigation uses `uiWorkspace`; members and external subagent records use the native `subagentchat` resource sidebar. DSH owns references, history loading and restoration. External projections remain read-only, while Team members retain native continuation rules. Model transitions are observed for each open Session. Only the main conversation controls the Diagnostics tab, preventing sidebar sessions from competing for the global entry.

This release continues to render ACP conversations through the native Assistant and ToolCallTree. Menu triggers, focus return, and dismissal with nested menus follow DSH semantics. The recovery panel explains when reconnect, blank rebind, or a new session applies; writes for one session are serialized, with local success or failure feedback. It states that existing history is preserved before confirmation, and failure details can be expanded.

An activity node waits for its initial binding and snapshot. A transient binding-pending result is not shown as an error or an empty log. ACP activity positions retain stable session and turn ownership, including consecutive tool turns without visible text. The host external-subagent projector is the persistence entry point for sidebar activity; receiving a client notification alone does not mean persistence succeeded.

External subagents show a running state while source tool evidence exists. Late terminal notifications remain trackable. If the source tool ends without a child terminal result, the child is shown as unfinished, while the tool's completed, failed, or cancelled status is recorded separately. A persistable result requires the child's own terminal event and must pass source and identity checks. ACP activity without verifiable identity remains activity data and does not create a separate subagent session. Claude's native external subagents show a bounded read-only result preview, not complete child-session history; results over 4000 characters are cleared and replaced with an omission notice to avoid unbounded accumulation or truncation before redaction.

When ACP invokes host tools through the bridge, their actual results remain visible as bridge activity. The current public Host interfaces do not provide native Session tool-call/result records or workspace-change events for every ACP tool call, and cannot always associate PTC subcalls with their parent call. This release preserves those host event-recording and PTC-association boundaries; it does not synthesize missing native events.

Main-conversation approvals read the original member requests from native `sessionStatus.pendingInteraction`. Batch actions still validate membership and request identity individually; later arrivals are not added to a captured batch.

Native continuable subagents default to 8 active instances, including cold resumptions. The Team member limit remains a separate setting. The generic delegation tool now defaults to depth 1; these Host settings do not fully control an external Agent's internal subtasks.

Native turn change cards depend on before-change snapshots and DSH tool events, so they cannot reliably capture ACP-internal file operations. ACP-provided diffs continue to be normalized into native `DiffBlock` data without inventing native tool execution records. ACP context usage likewise retains the Agent-reported used/size values; the native meter's DSH request estimates are not an equivalent replacement.

External read-only subagent records are published through the host child catalog with their parent ownership preserved. Restoring a V3 projection verifies its original digest before using the host V3 → V4 migration codec. Unsupported history and missing content remain intact rather than being reconstructed. Agent settings use native plugin configuration forms and revision checks; importing legacy settings preserves an already configured Agent list, including an empty list.

Parent controls and usage accept notifications only for their own ACP session; external children retain their separate native records. Admitted configuration writes complete before the next prompt. Headless hosts without the API model-selection projection use the native Session’s committed request header for continuity checks, including ACP binding verification, without enabling Web services.

While the activity view remains subscribed, transient initial-open and terminal-read failures continue to retry. The delay grows exponentially from 100 ms and is capped at 8 seconds; the retry count is not capped. Explicit stable errors are shown as unavailable, and data that has not loaded is never treated as an empty record set. Unsubscribing cancels the wait. Normalized process rendering starts only after the first snapshot arrives; unavailable data retains the native fallback.

The ACP conversation projection reuses the host's public builder and process-group state. Initial loading and node removal replace the snapshot; other updates apply changed nodes. Unchanged historical nodes and subscription adapters retain their identities, and activity windows are released when their nodes disappear. Rendering only prepares changes; committing updates and notifies subscribers. Node identities still need to be scanned, so not all work scales only with the delta size. If multiple assistant nodes unexpectedly share an activity window, original messages and the activity fallback are retained instead of repeating the same tools.
