# Native reuse and compatibility boundaries

[中文](native-reuse.md)

The current development branch targets DSH `0.2.2-rc.2`, using the exact official npm dependencies pinned in `package.json`; upstream source is only a test scaffold. README installation commands refer to the published release. DSH owns input admission, host tools, and native presentation. An external Agent owns its model loop, native tool permissions, and private context. The adapter translates protocol data between them and retains continuity, permission, and persistence behavior that public host interfaces cannot yet provide equivalently.

## Sessions and input

DSH's native inbox, pre-step hooks, and Session message persistence admit input. The adapter sends only the current admitted input over ACP; it does not rebuild AgentLoop or replay ordinary user history. A narrow exception delivers previously admitted conversation and instructions to the first Agent session of an unseeded, non-fork session that has always used the same ACP route, has no ACP execution records, and has never established an ACP binding. History from before route selection and explicit blank recovery do not use this path. During an active prompt, injection is possible only when the current ACP connection explicitly advertises safe injection; other handoffs cancel the old prompt, wait for its result and approvals to settle, then continue in the same Agent session. Native Agent CLI capabilities cannot replace the connection's advertisement. Effective DSH runtime context and a skill catalog may be passed to the Agent, but they do not install Agent-private skills or grant tools or permissions. Main model, reasoning, and search choices use native DSH selectors; Agent modes and pending member models remain bound to their ACP sessions rather than changing global defaults.

CodeBuddy model-specific reasoning discovery requires the actual `initialize.agentInfo.name=codebuddy-code` handshake and a valid `category=model` selector. It reuses the existing disposable session probe; a configured runtime label alone does not trigger model writes for generic Agents. A failed model probe does not borrow the default model’s reasoning choices, and discovery sends no prompt.

The ACP adapter normalizes execution facts for DSH `sessionProjections` to drive and restore; the projection is a rebuildable cache. The Sidecar still owns ACP bindings, dispatch state, and diagnostic transactions. Native Session logs and generic KV storage do not provide equivalent transactions. Existing history is neither rewritten nor cleared when the projection changes. An explicit blank rebind resends only AGENTS instructions in the current effective Host projection, preserving order and replacement/removal semantics; normal continuation and restoration do not resend them.

If the remote terminal result is confirmed but local persistence is pending, the current Host settles it before later input and does not replay completed tools; that pending state is not guaranteed to survive a Host restart. If remote acceptance remains uncertain, recovery stays gated: the adapter neither resends automatically nor hides lost context behind a blank session. Transient reads may retry; stable errors must appear as unavailable rather than empty data. DSH's native session-log ZIP does not include ACP Sidecar records. See the [README troubleshooting section](../README.en.md#troubleshooting-and-feedback) for export and sharing.

If the directory or transport becomes stale after input admission but before ACP prompt dispatch, with no Agent-initiated turn waiting for adoption, the runtime reports `ACP_PROMPT_NOT_DISPATCHED`. The adapter clears only that input’s dispatch guard and preserves the original binding and consumed-history head. Retrying restores the same Agent session without a blank reset. A failed local clear remains gated by settlement; dispatched or automatic turns with unknown outcomes do not use this path.

The explicit Host root service `acpHostContinuity` owns pending execution, recovery gates, and local settlement queues. Plugin reinstalls within that Host reuse these owners without clearing unsettled work; different Hosts and standalone adapters do not share a module-level registry. Final Host shutdown stops new resource leases, settlement sinks, and background retries, then waits for registry tools, fork registration, projections, and final writes before releasing dependencies, the Sidecar, and remaining queues. A cleanup failure still permits subsequent resource cleanup and is reported; withdrawing a dependency does not certify that a tool finished.

An ordinary fork seeded with the parent's completed history must establish the parent binding, idle state, latest semantic cut, and actual ACP `session/fork` capability. If those conditions cannot be established or the fork fails, the adapter does not call `session/new` to present a blank session as inherited history; an uncertain dispatched result retains the recovery gate. The public execution guard rejects `subagent_fork` early only when its arguments explicitly select an ACP target and the parent has completed history with a currently active turn. This tool also permits explicit native child routes, and public tool definitions do not expose the effective default route when arguments are omitted, so an ACP parent alone cannot justify hiding the whole tool or rejecting a Team fork. Native targets retain Host admission; unknown defaults, custom tools, and direct subagent services rely on the final target's seeded-fork admission. The pinned Host does not expose complete target-route resolution or an adapter preflight for native fork menus and creation. A menu may remain clickable and a DSH fork record may already be created, but that does not permit an ACP blank fallback or subsequent prompt dispatch.

## Tools, permissions, and optional capabilities

Qwen Code background and scheduled turns are adopted through native jobs and AgentLoop. A background completion notice wakes the Agent and adopts the turn Qwen has already started; other inputs admitted in the same step are sent in order after that turn has a confirmed terminal response. Only an explicit terminal receipt with matching session/turn identity and a supported reason can settle an automatic turn normally. Unknown, empty or missing reasons retain outcome-unknown recovery and block retained input. An announced background turn with a matching `turnComplete:true, partial:true` response marker also retains an unknown outcome on a subsequent `end_turn`; explicit cancellation and other supported terminal reasons keep their own semantics. Upstream errors without any incomplete-response marker cannot be reliably identified by the adapter. Active-work snapshots report liveness: hold disappearance, model usage or silence cannot prove whole-turn success or cancellation. Current Qwen cron/loop turns lack a whole-turn terminal marker; their output is adopted, but missing terminal reporting eventually enters unknown-outcome recovery rather than successful completion. An unconfirmed Stop closes the connection and retains an unknown outcome. Qwen questions use the native question panel, and private extensions apply only to an identified Qwen Agent. See the [E2E guide](../test/e2e/README.md) for separate fixture and real-Agent coverage.

The bridge exposes only tools assembled by DSH for the current admitted request that remain active in the session scope. It borrows the exact `ResolvedToolSet` admitted for the current Host step and uses the selected native or PTC executor through the batch `tools.execute` API, including argument checks, hooks, and tool rules. PTC `run_code` is an executor-owned transport rather than a registered tool; removed tools or narrowed scope revoke the corresponding targets in the old directory. Requests confirmed as coming from this bridge but naming unregistered tools are rejected instead of offering approval for an unexecutable call. The Agent's own shell, file, and model calls remain Agent-owned and do not become DSH tool events through the bridge; plugins requiring native model calls, PTC-internal call identity, or loop control still need separate adaptation. The Host MCP client and one-shot external subtasks cannot replace an interactive ACP session or its native subagent communication bridge.

ACP Auto/Ask handles the Agent's actual requests for permission to use DSH tools. Ask presents those requests for user confirmation; it neither requires an approval prompt for every tool call nor changes Agent mode. This setting is neither native Auto Review's LLM risk assessment nor an expansion of DSH tool authority. Existing session policy snapshots are retained. New local managed children without a separate snapshot read the verified runtime root's policy live, independently of the Team toggle. A native-model root supplies the ACP default policy; independent forks snapshot their inherited policy once. Devin's ACP permission requests do not reliably identify enterprise Ask requirements, so actual requests require a human answer even under Auto. The adapter does not automatically choose a one-use, persistent, or bypass grant. Other Agents retain their existing tool-identity and option checks. Enterprise denials and Agent-owned permissions remain enforced by their respective systems; moving a request to the parent page or changing execution identity cannot override them.

Unambiguous one-use allow/reject requests reuse native approval, and the parent page answers the child's original pending carrier. Multi-choice permissions retain their original options, IDs, and scopes through a native question presented by the exact live runtime root. The root owns only the presentation; the answer still resolves the original child ACP request. The child Sidecar audit records the presentation source for `session/request_permission`; Codex elicitation retains its own response path without fabricating that permission audit record. The Host checks live instances and every ownership edge before presentation and before accepting an answer. Cancellation, connection loss, or instance replacement invalidates late answers. Multi-scope choices are neither reduced to one use nor included in batch approval; restoring presentation does not replay tool operations.

This works independently of Teams and preserves the child's native delegated `never` policy for DSH tools. Independent forks and read-only external-subtask projections are not treated as managed children. Cross-session lists check resource access at each level. The pinned Gateway delivers interaction requests and accepts answers only from owner clients, so root presentation does not broadcast child details to read-only clients. Ordinary clarification and plan review retain native caller restrictions; only recognized ACP permission requests and identity-verified Codex permission-scope forms use delegated presentation. Native services continue to own question cards, waiting, and answers. The adapter only associates the original request with its presentation lifetime, without another approval broker or user switch.

RC.2 still blocks model changes in an established ACP session when its catalog omits context capacity: native model-switch compaction raises `MODEL_SWITCH_COMPACTION_FAILED` before the ACP prompt, including when waking a member with a newly selected model. The adapter offers an existing session the choice of retaining its model or creating an independent session, and rejects bypasses at Host admission. The new session does not inherit conversation history. Other models are disabled for established members, while their committed model remains selectable to clear a legacy pending selection. Initial member model selection and same-model reasoning changes remain available; none of these actions changes the global default.

This guard avoids the known failure without implementing model-switch compaction. The adapter neither invents model capacity nor swallows compaction failures or changes shared native presets. Full model switching and auxiliary compaction still require separate Host lifecycle support.

Native Auto Review, automatic titles, and `/compact` auxiliary model calls currently lack the ACP admission identity required for ordinary prompts, so equivalent support cannot be promised.

ACP file writes preserve bytes, reject final symlinks, recheck content hashes after staging and before publication, and retain new-file conflict protection. Host `writeText` writes UTF-8 content unchanged and normalizes only the returned diff `after` to LF. It is not an equivalent replacement because Host path resolution follows final symlinks and its version check occurs before staging. Before the native `create_worktree` or `working_directory` tools change the directory, the adapter must establish support for a context-preserving `session/fork`. Supported Agents transfer the binding after the old execution and Host tools settle; unsupported Agents are rejected before Git or directory side effects. A known pending handoff can continue later, while an uncertain dispatched result remains under explicit recovery. The RC.2 `working-directory/access` waterfall now guards both tools and direct service callers. The old `working_directory` tool special case is removed; the `create_worktree` guard still runs before Git effects. Initial loading, an initial directory choice with confirmed absence of a binding, and physical same-directory validation remain available. A bound session still needs a context-preserving fork handoff for a real directory change. An idle session has no active execution to own that handoff, so the change is rejected before commit, including Forge’s Continue in project action. `ensure` retains unchanged-directory validation and guards implicit fallback after directory loss; invalid directories keep native errors. Binding read failures and route or owner changes during asynchronous checks block the commit. This is pre-commit service admission, not an atomic transaction with concurrent external file deletion, and it never silently creates a blank conversation.

User-facing official optional bundles are enabled through native DSH Plugins; the adapter adds no second switch. Installation, code import, service activation, and availability in the current session are distinct states. RC.2's per-session Team toggle controls task features; turning it off neither deletes the native subagent tree nor revokes existing ACP approvals or member settings. Native `ui-subagent` owns member discovery and navigation, while the official Team UI owns the task board. ACP contributes only member settings through the public `subagent.footer` slot and uses the native Modal for model, mode and interruption controls. These contributions follow the native catalog UI through disable and re-enable, without a second header entry. ACP image capability reaches native tools only when the current caller, Session, runtime generation, confirmed model, and live connection match; unknown capability is not mislabeled text-only. The official `appendPluginRecord` write surface does not include this plugin and cannot replace the Sidecar.

Member settings reuse the native Modal's keyboard and focus management. Its public key-capture hook lets the foreground dialog handle Escape before the catalog behind it, while open menus and IME retain their own keys. If the catalog has closed and its footer opener has unmounted, the RC.2 Modal has no public return-focus target: closing leaves focus on the page body. Tab still reaches usable controls, but focus restoration remains incomplete. The adapter does not compensate through private DOM access or forced composer focus; a dedicated browser diagnostic records this remaining interaction limit.

Remote UI operations use DSH caller and Session resource authorization. Team management checks both Lead and member scopes when it accesses both, and cross-session lists return only entries currently readable by that caller. This operates separately from Agent tool approval and adds no ACP login or permission configuration. Membership uses native `subagents.rootOf` and `listDescendants`, with additional checks of the local child descriptor, ACP binding and exact live instances around asynchronous operations. Full named paths supply display and addressing, not authorization. Native roots and descendants using different ACP Agents are supported. Interruption uses the target member's own `subagents/interruptByUser` permission; its receipt means accepted, not stopped. The old Team roster, member-model backfill and copied creation policy are removed. Native services own child creation and messaging; final-target admission retains ACP continuity restrictions.

Directory changes revoke individual targets without closing a live MCP connection merely because its directory becomes empty. Pending approvals bind the original tool registration and prompt generation, cancel on revocation, and revalidate before replying; unrelated tools and Agent-native permissions remain independent. A new registration cannot inherit old authority by matching its name or schema. A new safe request admits the current directory; a suspended prompt with a changed directory drains before continuing through the Agent's recovery capability, rather than bypassing recovery through steering. Removing the service or Agent still closes the connection. Batch failures expose only redacted, bounded messages and structured fields, never arbitrary cause objects.

Ordinary forms retain every schema field and its explanation. Native Skip omits optional fields, and `items.anyOf` retains multi-select semantics. A name suffix does not establish a question relationship, so `_custom` fields are not automatically merged. Missing answers cancel required fields and recognized permission scopes. The native card may still show a separate optional page; this does not provide an optional form that submits without visiting Skip.

## Presentation and observability limits

Opt-in live diagnostics belong to the Host root service `acpLiveDiagnostics` or a collector owned by one standalone check. There is no sink or additional logging by default. Reinstalls within one Host retain that owner; different Hosts and runs keep separate sinks. Revocation stops new records and waits for accepted writes, while write failures remain observable. Diagnostics are neither authorization nor proof of completion.

Diagnostics, Agent controls, and plugin settings show hover feedback only under `(hover: hover)`. Selected, expanded, disabled, and keyboard `focus-visible` states remain independent of that capability. The narrow Diagnostics toolbar wraps its filter and action groups, with a flexible search field so every control remains accessible. The 390px light/dark touch regression uses Chromium input-capability emulation; a narrow desktop or ordinary Electron window is not equivalent touch coverage.

Incremental ACP terminal output uses the native jobs output stream for retention and presentation, while ACP keeps its own independent output snapshot. Active terminals and completed but unreleased terminals retain native records and readable output. Once process-range exit, the existing release-audit path and native waiter settlement are confirmed, releasing the terminal removes its presentation record while retaining Sidecar and Session history. Job grouping, stopping and clearing finished rows use the native UI. Clear only hides rows in the current component; it neither deletes backend records nor stops live work. A Qwen task cancellation reply describes the request outcome, not task termination. Failed or unconfirmed cancellation keeps native `stopping` with a progress explanation; normal settlement after cancellation relies on an explicit terminal notification or snapshot. Elapsed time or disappearance from a snapshot does not prove termination. Connection closure awaits the existing managed-process cleanup; an unconfirmed exit is reported as a cleanup failure without claiming the task stopped.

Work-detail display and collapse timing follow the native DSH settings. Committed ACP responses keep their native placement and obey the native All/Final reply preference; the adapter no longer forces them to the turn level. Process content still collapses, and the latest native answer continues to own the turn footer actions. ACP journal aggregates belong to the whole turn's process, without creating a separate analysis step; an empty journal adds neither a completed-analysis group nor spacing. ACP detail cards also use native disclosure state: collapsing the outer process resets inner cards, while changing the display mode preserves manual expansion. For the pinned renderer, private slots retain their registry aliases while their DOM `data-slot` names are restored to the native names, so native CSS continues to own row spacing.

ACP notifications are normalized before native DSH Assistant, tool tree, Diff, plan, and process-group presentation; native sessions retain their renderer. If an exit status, file line count, or historical content position is absent, the UI shows known facts or generic details instead of inventing numbers, order, or Host execution events. ACP tools without a native trajectory event omit the View action instead of substituting a JSON modal. A single absolute location that matches the file target anchors historical file opening across working-directory changes. Truncated diagnostics cannot become a complete Diff. ACP plans are projected for observation only; the adapter does not call `todo_write` in response or force unfinished tasks to completion.

In conversation activity cards, plugin-generated tool placeholders and terminal, diff, resource and content titles use the Client locale, identified by structured provenance and activity identity rather than English display text. Agent-authored titles remain verbatim; legacy records without provenance and oversized details truncated into unparseable data retain their original text. The native picker’s “Agent current configuration” label remains untranslated: RC.2 exposes a single label slot without per-model fallback, so taking it over would affect other plugins. Native aria/title and `/model` names also remain unchanged.

In DSH `0.2.2-rc.2`, the native per-turn changed-file summary requires a native Session `tool/result` event; a turn using only Agent-owned ACP tools does not automatically produce it. Bridge calls through `tools.execute` run real execution hooks but do not imply that the native AgentLoop appended this Session event. A per-tool native DiffBlock and the per-turn summary follow separate paths. “Show code work views” only controls the visibility of existing change cards, without collecting missing file changes. Explicit Markdown file links still use native previews; automatic links for inline-code filenames depend on native produced-file or presented-file records.

The batch API can log bridged Host calls with an admitted step identity; this adapter does not yet enable that separate logging path. Public Host interfaces cannot reliably capture the Agent's internal file operations. Actual ACP diffs may be shown through native DiffBlock, while context usage remains Agent-reported. External subtasks become read-only child sessions only after source, identity, and child-terminal evidence is verified; a result preview does not claim to be complete private history. Unrepresentable attachments or output are explained rather than silently dropped.

Agent `usage_update` notifications still supply context occupancy. Token usage in a `session/prompt` response is not written into DSH's exact native accounting: no reliable contract across Agents establishes whether counts describe one turn or the whole session, and input may already include cache traffic. Cumulative baselines after restore, fork, or restart cannot be inferred either. Native accounting requires those semantics to be established and translated into DSH's per-attempt, disjoint input/cache buckets first.

See the [E2E guide](../test/e2e/README.md) for verification scenarios and the [release guide](releasing.md) for publishing and rollback (both in Chinese).

## Agent differences and the optional preset

`src/agents/` contains stateless protocol differences and connection options. Generic ACP Agents need no module; transport, approval, dispatch and recovery remain shared. `SessionControls` owns snapshots, mode intents and serialized control writes, draining accepted writes before teardown. `ToolDirectoryOwner` owns one MCP lease's tool identities and permission validity. `AcpProfileAdapter` retains dispatch, settlement and recovery ordering; the bridge retains accepted execution and feedback draining. See the [compatibility guide](agent-compatibility.en.md) for contribution boundaries.

The bundle adds the optional native `acp-adapter` preset, displayed as ACP, using public RC.2 plugins. The profile-scoped adapter runtime stays outside this composition. Standard, PTC, Minimal and Creator remain unchanged, as do existing sessions and user defaults. ACP omits Host compaction, `/compact`, Host planning, delegation and plugin management. It neither limits private Agent capabilities nor bypasses existing-session model-switch guards. The model catalog remains global; native-model sessions should select the Host preset they need.

Creator reads DSH development documentation through the official unified `dsh-doc` skill, using Host skill-reading and plugin-loading tools. The adapter neither installs skills in private Agent directories nor requests removed entries such as `cordis-plugin-development`. Reading a skill grants no tool authority; plugin loading still follows the shared directory-revocation and recovery sequence.
