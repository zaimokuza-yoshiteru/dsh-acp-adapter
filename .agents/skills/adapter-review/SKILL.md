# Review the adapter

Verify the live PR base and exact head before treating a cached diff or file as current. Read surrounding implementation and both sides of changed interfaces. Prioritize incorrect behavior, lifecycle, security and compatibility over style; a review does not authorize GitHub comments, merges or unrelated edits.

Read the owning requirements and relevant sections of the pinned upstream's `docs/defensive-patterns/` before reviewing changed contracts. Requirements and implemented source take precedence over a remembered architecture rule or a proposed note.

Prefer official features when they retain current behavior without extra user setup or operations. For each affected business domain, trace both sides of the pinned upstream interface, its current producers and consumers, and manifest-driven entry points before deciding what to replace. A simplification must remove maintained work rather than move it or silently drop capability.

Review the user's decisions as well as the implementation: installation and credentials, model and mode selection, tool approval, continuation, recovery, and optional features. Name every new configuration, choice, confirmation, or migration step and the behavior it enables. Prefer the existing native entry and an automatic, proven continuation; do not replace required approval or unknown-outcome review with an implicit action. Known unavailable actions should be described by their Host owner rather than offered for the user to discover by trial and error.

For optional capabilities, distinguish installed packages, imported code, registered hooks, active services, and per-session availability. Follow the official bundle/profile entry through enable, disable, late mount, and disposal. A hidden component or erased type import is not evidence of lazy module loading; a common ACP safety guard is not an enabled experimental service. Do not add a second user-facing switch or infer permission from service presence. Consult relevant pinned upstream `.agents/notes` alongside skills: implemented notes explain current decisions, proposed notes require source verification, rejected notes preserve scoped counterexamples, and archived notes are historical only.

Use [native reuse](../../../docs/native-reuse.md) for ownership. For input changes, trace the current ACP connection's capabilities, native admission, handoff, and recovery through implementation and focused tests; an Agent CLI's steering support alone does not establish ACP support. Check these where the change reaches them:

- Trace cancellation, disposal, late completion and restoration through the shipped Loader, ACP process, MCP bridge or browser entry. A directly mounted mock plugin does not certify those paths.
- Inspect the actual Agent-visible prompts, schemas, tool results and context updates. DSH skills use the current DSH loading route; they are not installed into an Agent's private skill directory and do not grant tools or permissions.
- Keep initial model-facing context focused on purpose, actions and necessary constraints. Deferred details need a reliable discovery route, bounded results must identify omissions and retrieval paths, and permissions or destructive effects must be visible before the action. Say each fact once; when changing tool definitions, compare prompt cost and total work rather than assuming shorter copy is better.
- Distinguish new Agent requests from bridge retries using identifiers and side effects. Keep uncertain remote acceptance separate from confirmed completion with pending local persistence.
- Expected failures use stable typed identifiers, not parsed display text. Identify the state and reporting owners, committed or unknown effects, cleanup guarantees and the safe next action. Catching an error does not restore state; dependent work resumes only after its owner establishes the required conditions. Verify the resulting state and visible report.
- Verify assertions observe external state, events, logs, files or exits. Require a relevant negative case for a new guard; neither coverage nor an Agent's self-report establishes the behavior.
- Match new documentation and diagnostics to the owning implementation, including serialization and verification limits. Do not expand one Agent, platform or scenario result into a complete matrix claim.

Review reachable plugin entries and helpers for scoped ownership as well as functional behavior. Mutable module, static, process or `globalThis` registries remain singleton state even when they use WeakMaps or generation keys; scope them to an explicit Host/service owner. Identify any existing cross-reinstall recovery requirement before replacing such state, and preserve pending approvals, settlement and recovery evidence. Immutable lookup tables are not lifecycle owners.

Trace teardown in the shipped Cordis runtime: sibling disposers can run concurrently, so `inject`, reverse registration, or an abort/kill request alone does not prove a dependent task has settled. Stop new admission, await accepted work and durable writes, keep dependencies and listeners alive until their last use, then release them. For a changed lifetime, use a controlled promise to pause a consumer before its final dependency use, unload the provider/root, and assert completion and resource availability in the owning regression. Report the concrete interleaving and impact; do not infer a leak solely from a missing injection declaration.

For native UI changes, reuse DSH components, tokens, locale-owned text and existing interaction patterns before adding alternatives. Verify affected light/dark and window-edge states; menus must dismiss, remain inside the viewport and escape clipping. Keep transient feedback in a surface that survives the action; failed operations retain useful content. Check affected macOS/Windows chrome behavior without changing global spacing to repair one local region. Use the focused browser scenario and inspect screenshots when geometry or appearance matters; a CSS assertion alone is insufficient visual evidence.

Check affected layouts at 390 CSS px. Allocate space and wrap titles/actions before truncating or moving actions into a menu; primary actions, important state and otherwise unavailable error details stay accessible. Preserve focus across width changes while the focused control survives. Use `@media (hover: hover)` for hover styling, familiar icons with accessible names, and the native tooltip/touch pattern. Avoid duplicate ACP scrolling, folding, release-refresh prompts or composer command UI when the native owner already handles the event. Conversation definitions must respect native exclusive event claims, so an approval reply is not rendered or submitted twice.

Use [adapter-validation](../adapter-validation/SKILL.md) to select evidence rather than rerunning an exhaustive suite during review. Report each actionable finding with its location, impact and supporting observation, and state remaining uncertainty. When asked to implement, repair the owning component within the authorized scope.
